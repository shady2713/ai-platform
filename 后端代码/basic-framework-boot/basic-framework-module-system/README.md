# system 模块

安全信号在认证判定和会话删除结果处记录，语义与处置见[安全指标说明](../../../docs/security/security-signals.md)。
会话删除服务返回实际删除行数；指标监听删除结果事件并在事务提交后累计，回滚与无会话均不增加计数。
登录失败的 Redis 原子结果区分未锁定、新锁定和已锁定，只有新锁定增加账号锁定计数。

`basic-framework-module-system` 提供账号、权限、菜单、字典、通知和短信等管理后台基础能力。

新安装只提供一个根部门，封存的种子管理员归属该部门；示例组织和旧操作类型字典的清理边界见
[ADR 0043](../../../docs/adr/0043-prune-unused-initialization-data.md)。

## 短信客户端扩展契约

- 新供应商通过 `SmsClient` 适配；可恢复的 SDK、网络和报文故障以 `Exception` 表达。
- 供应商实现通过包内 `SmsHttpClient` 使用唯一 HTTP 出口；生产构造器绑定 `HttpUtils`，测试构造器隔离真实网络并验证 URL、签名头、请求体及成功/失败响应映射。
- 发送链路会记录并降级普通供应商异常；`Error` 表示 JVM 或运行时不变量已失效，框架不得将其转换成业务失败后继续运行。
- 供应商异常只在日志中保留脱敏后的有界堆栈，短信发送记录只保存异常类型；模板校验对外返回固定错误文案，不传播供应商异常正文。
- 共享客户端缓存按渠道编号原子更新；渠道供应商类型变更时替换客户端实现，不得在旧供应商实例上仅刷新配置。
- 短信渠道 API Key 与 API Secret 均以版本化 AES-GCM 密文持久化；读取旧版明文 API Key 时以比较并更新方式完成兼容迁移，接口和日志不得回传凭据原文。
- 第三方发送响应只有 `success = true` 才记录为成功；空值或 `false` 均记录为失败，避免不完整响应被误判或触发二次异常。
- 登录与重置密码验证码模板的短信日志会将正文和 `code` 参数替换为 `[REDACTED]`；向短信供应商的实际发送参数不变。

## 短信状态回调契约

- 回调默认关闭；启用时 `SMS_CALLBACK_TOKEN` 必须是随机的 64 位十六进制值。
- 供应商必须传入 `X-Sms-Callback-Token` 请求头或 `callbackToken` 查询参数；无效凭据在解析业务载荷前拒绝。
- 回执按短信渠道与供应商流水号关联，不单独信任外部传入的本地日志编号。
- 回执更新保持单调且幂等：成功可覆盖初始化或失败状态，失败只可覆盖初始化状态；重复回执和成功后的迟到失败视为已处理，不得回退最终成功状态。
- 配置前缀为 `basic-framework.sms.callback`，回调还受 IP 维度限流。

## 验证码接口防护

- 公开的 `/system/captcha/get` 与 `/system/captcha/check` 按“接口 + 客户端 IP”限流为每分钟 30 次；请求体不参与限流 key，避免通过变更验证码参数绕过限流。
- 登录图形验证码开关由 `basic-framework.captcha.enable` 配置拥有，默认启用；local 与 test profile 必须显式关闭，业务服务不得自行提供默认值。
- 同一手机号的短信验证码发送受分布式锁串行化，频率与每日上限检查不会被并发请求绕过；不同手机号可并行发送。
- `aj.captcha.aes-status` 固定为 `false`，启动时拒绝缺失或开启该配置。验证码密钥会同时下发给浏览器，客户端 AES 无法替代 TLS，也不提供额外保密性；前后端统一使用 TLS、短时令牌和原子核销保护验证码协议。

## 匿名认证账号枚举防护

- `/system/auth/send-sms-code` 对未知手机号返回与已存在账号相同的受理结果，但不会创建或发送短信验证码；客户端不得据此判断账号是否存在。
- 重置密码先原子消费一次性短信码，再查询账号；验证码有效但账号已删除时返回通用成功结果，不修改任何密码。
- 用户名不存在或账号已临时锁定时，登录链路仍使用部署实际的 `PasswordEncoder` 执行一次假哈希校验，避免通过 BCrypt 成本差异推断账号状态；假哈希只在启动期生成并在请求间复用。
- 图形验证码、短信码校验和客户端 IP 限流继续生效；通用成功响应不代表短信已发送或密码已修改。

## 密码哈希生命周期

- 用户名密码验证成功且账号启用后，使用 `PasswordEncoder.upgradeEncoding` 判断存量 BCrypt 哈希是否低于部署当前工作因子；无需升级时不写数据库。
- 升级写入必须同时匹配用户编号和认证时读取的旧哈希。并发改密、管理员重置或删除账号会令条件更新自然失效，机会式升级不得覆盖新凭据，条件写入失败时拒绝本次登录。
- 重编码只改变哈希盐值或工作因子，不改变密码语义，因此不撤销会话、不写操作日志；编码或存储异常保持失败，不降级签发登录会话。

## 刷新令牌 Cookie 边界

- 刷新令牌仅以 host-only、`HttpOnly`、`SameSite=Strict` Cookie 传递，Cookie 路径限定为管理端认证接口。
- 刷新与登出在消费 Cookie 前校验浏览器 `Origin`：仅同源或 `basic-framework.web.cors-allowed-origins` 中的源可通过，防止同一主域下的不可信子域触发令牌轮换或登出。
- 未携带 `Origin` 的非浏览器调用不会被该检查误拒绝，但仍须持有 HttpOnly Cookie；任何新增的 Cookie 凭据消费端点必须复用此校验。


## 超级管理员授权边界

- 角色菜单、角色数据范围和用户角色分配必须把当前操作者编号传入 `PermissionService`，不能只依赖 Controller 的权限注解。
- 一次变更只要涉及 `super_admin`，无论授予、撤销还是能力调整，操作者都必须实际持有启用中的 `super_admin`；校验在读取或写入授权关系前失败。
- 普通角色仍按各自的专用权限管理；`super_admin` 因绕过普通权限与数据范围而采用更严格的授予者上限。

## 角色数据范围安全默认值

授权判定中的角色、用户角色、角色菜单、菜单状态和部门子树直接读取数据库，不使用跨请求缓存。
撤销权限后的迟到 Redis 回填不能恢复授权；字典等展示数据仍可缓存。角色批量查询和部门层级单次
查询避免逐项访问数据库，同一数据范围计算内复用已读取的部门子树。普通角色授权所用菜单自身及全部祖先必须
启用；缺失祖先、循环或未知状态均拒绝授权。ArchUnit 阻止授权服务重新依赖 Spring 缓存。
设计依据见 [ADR 0035](../../../docs/adr/0035-read-current-authorization-state.md)。

- 新建角色固定从 `SELF`（仅本人）数据范围开始；调用方传入的范围不会在创建命令中生效，扩大范围必须经过独立的数据范围分配权限和审计入口。
- `system_role.data_scope` 的数据库默认值同样为 `SELF`，受控脚本或其他非 ORM 写入不会因漏传字段自动获得全部数据权限。
- 存量角色的已配置范围不会被迁移改写；未启用数据权限规则的业务表不受该默认值影响。

## 操作审计隐私契约

- 用户资料变更仍以原值判定是否发生差异，但写入操作日志的邮箱和手机号只保留掩码；格式异常或非文本值统一记录为 `[REDACTED]`。
- `scripts/check-sensitive-diff-log.mjs` 在 contracts 门禁中要求所有带 `@DiffLogField` 的邮箱、手机号和电话字段绑定对应脱敏函数，防止新增字段回退为明文审计。

## 登录与改密

登录仅使用账号密码和图形验证码；强制改密账号在设置新密码前不能获取会话。自助改密和认证前改密均以认证时的旧摘要条件更新，拒绝禁用账号及并发覆盖；认证前改密还要求强制标记。成功改密撤销会话；登录成功日志与会话签发同事务，失败登录审计独立提交。种子账号默认禁用，激活步骤见根目录 docs/deployment.md。

管理员重置密码也须确认实际写入一条账号记录；校验后并发删除账号时返回账号不存在，不记录成功或发布改密撤销事件。

## 会话一致性

会话以 MySQL 为唯一权威，按访问摘要的唯一索引校验，不在 Redis 复制可用于鉴权的会话状态。签发必须提供已认证的密码摘要，在当前事务锁定账号并核对启用状态、改密标记和当前摘要；刷新与按用户撤销使用相同账号行锁，按用户再会话的顺序写入。多用户撤销按编号排序。代价是每次令牌校验需要一次索引查询，扩容时按实际请求量评估连接池与数据库容量。并发与回滚契约由真实 MySQL 集成测试验证，决策见 [ADR 0036](../../../docs/adr/0036-serialize-account-and-session-changes.md)。

## 刷新与登出并发

刷新令牌包含稳定撤销凭据和一次性刷新秘密，两部分分别来自 256 bit 随机数。数据库只保存
摘要；刷新仍需完整的当前令牌，任意旧代只能撤销同一会话。这样，刷新已提交但 Cookie 响应
尚未到达时，登出仍能使迟到 Cookie 失效。旧版令牌在首次刷新时升级，数据库变更见 V44，
并发兼容决策见 [ADR 0039](../../../docs/adr/0039-revoke-session-across-refresh-generations.md)。

## 联系方式唯一约束

手机号与邮箱的空白值表示未提供，默认使用 NULL。数据库函数唯一索引只约束未删除用户，
防止并发预查询同时放行；软删除后的值可再次使用，不受历史删除次数限制。迁移遇到已有
重复活跃联系方式时拒绝继续，保留原数据供部署者核查归属，见 [ADR 0040](../../../docs/adr/0040-enforce-active-contact-uniqueness.md)。

## 用户导入

导入使用与用户表单一致的昵称、联系方式及枚举约束。更新前先解析既有用户编号，允许保留本人的手机号和邮箱，仍拒绝占用他人联系方式。新账号固定禁用并携带强制改密标记，使用随机初始密码；现有账号保留密码及强制改密标记，填写的状态参与更新，留空时保留原状态。导入更新在同一事务撤销会话，避免保留旧部门、昵称或已禁用账号的访问能力。

更新已有用户时，导入表格中留空的部门、邮箱和手机号保留原值；批量导入不提供解绑语义，解绑使用用户编辑或个人资料接口。

导入更新只有实际写入一条记录才计入成功。校验后并发删除导致写入失败，或数据库唯一约束拒绝竞争写入时，本次导入事务整体回滚。

## 用户资料清空契约

管理员编辑用户采用完整表单语义：部门、邮箱、手机号和备注可清空；岗位未传或为空时，同一事务将 `system_users.post_ids` 写为 `[]` 并删除对应岗位关系。个人资料中的空邮箱、空手机号表示解绑，未传头像或性别保留原值。两种写入各有专用字段白名单，不允许资料编辑改变密码或强制改密标记；个人资料也不能修改部门、岗位或账号状态。

编辑先锁定并读取当前用户行，再以当前读计算岗位差量；即使外层事务已经持有旧快照，也不会遗漏中间提交的岗位变更或应撤销的会话。
