# 报表受控分享权限说明（X11）

定义报表在**已登录且获授权主体之间**的分享语义（FR-05/FR-28/FR-29/FR-40）。实现位于
`service/report/share`（`AiReportShareService`）与 `controller/app/v1/report/AiReportShareController`，
持久化为 `ai_report_share`（凭据，soft-delete）与 `ai_report_share_access`（访问审计，append-retention）。

## 1. 两种权利，刻意分离

| 权利 | 载体 | 回答的问题 | 由谁判定 |
|---|---|---|---|
| **报表可见权** | 分享凭据（`ai_report_share`） | "谁能打开这份分享、能看到哪个版本" | 授予者签发；撤销/到期/授予者状态即时约束 |
| **源数据读取权** | 接收者自己的 A03 授权 | "这次读取是否真的出库内容" | 每次读取按接收者**当前**授权逐项复核 |

- 凭据**不携带**任何数据权限：接收者拿到的不是授予者的权限，而是"一个入口"。
  入口后面每项资源依赖都按接收者自己的 A03 范围指纹复核
  （镜像 `AiReportServiceImpl.requireScopeStillCovers` 的历史再鉴权：
  `reauthorizeHistorical` 判定放行且复现保存时的指纹才算覆盖）。
- **降级态**（`contentAuthorized=false`，`reasonCode=scope-uncovered`）：凭据有效、HTTP 200，
  但 `specJson`/`dataJson`/`asOf`/`completeness` 全部为空——隐藏统计与快照**不出库**。
  可见性是授予者有意签发的，所以不抛 404；内容覆盖不了，所以不给内容。
  接收者无源权限时看到的只是"这份分享存在"，拿不到任何数字。
- **复制 reportId 无效**：分享读取只认令牌摘要（`token_hash` 唯一索引定位），
  报表编号、版本编号与分享编号都不构成读取入口；直接调报表读取接口仍按报表归属判定拒绝。

## 2. 签发（create）

| 规则 | 语义 |
|---|---|
| 授予者 = 报表所有者 | 当前 USER 主体必须与报表归属（应用 + 主体类型 + 外部用户标识）三元组一致；否则 404（越权与不存在同语义，防编号枚举） |
| 仅 USER 主体 | APP 主体（应用身份）不能作为授予者或接收者（403）；分享是"人给人"的功能 |
| 接收者必须真实可用 | `AiSubjectService.findActiveSubject` 必须命中且不能是自己（400） |
| 版本在签发时固定 | `version_no` 取请求版本号（缺省为报表当前最新版本），必须真实存在（404）；报表新增版本不改变已签发分享的内容 |
| 去重 | 同报表 + 同接收者已有 `ACTIVE` 分享 → 409（`AI_REPORT_SHARE_DUPLICATE`）；撤销/过期后允许重新分享（服务层判定，不用唯一索引表达"不重复"） |
| 过期时间必须在未来 | `expiresTime` 缺省为长期有效；给了就必须晚于当前时刻（400）；写库截断到秒 |
| 凭据只存摘要 | 明文令牌 = 32 字节 SecureRandom → Base64URL（无填充）；库里只有其 SHA-256 小写十六进制摘要。**明文只在创建响应出现一次**，之后平台任何接口、审计与日志都不再返回明文；摘要不可反推，库泄露不等于凭据泄露 |

## 3. 读取（read）与五类即时失效

读取按顺序判定，前五类失败对外**同一个 404**（`AI_REPORT_SHARE_NOT_EXISTS`，防枚举：
不帮攻击者区分"凭据错"与"凭据无"），稳定原因只写进访问审计；每次读取（含拒绝）追加一条
`ai_report_share_access`（结论 + 原因码 + 是否真的出库内容）。

| 顺序 | 判定 | 失败原因码 | 即时语义 |
|---|---|---|---|
| 1 | 凭据摘要能定位分享，且当前主体 = 接收者（USER） | `subject-mismatch` | 凭据不可转借：换人、换应用都读不到 |
| 2 | `status != REVOKED` | `revoked` | **撤销立即生效**：分享签发的那个（历史）版本同样拒绝 |
| 3 | `status != EXPIRED` | `expired` | 已物化的过期直接拒绝 |
| 4 | `expires_time` 未过 | `expired` | **到期即时生效**：读取时惰性物化为 `EXPIRED`（CAS，不设常驻扫描任务）；并发撤销时物化让位给撤销，本次读取照样拒绝 |
| 5 | 授予者主体仍可用 | `grantor-unavailable` | **授予者离职/停用默认拒绝**：分享是"人给人"的授权，人走了入口就关闭，不留下永久可见通道 |
| 6 | 内容范围复核 | `scope-uncovered`（**降级态，不抛错**） | 接收者当前源权限覆盖不了分享时的范围：可见性保留，内容全空 |

- 撤销是**乐观锁 CAS**（仅授予者本人 + 仍 `ACTIVE` + 版本匹配）；0 行时按当前事实回读：
  已撤销按幂等成功返回，仍 `ACTIVE`（版本冲突）或已 `EXPIRED` 报 409。
- 授予者重新启用（主体登记为可用）后，未被撤销/未过期的分享恢复可读——失效原因是"授予者不可用"，
  主体恢复即消失；被明确撤销或已物化过期的分享不会因为主体恢复而复活。
- 分享行软删除后凭据摘要不再可用（唯一键保留在删除行上，同一凭据不可复活）。

## 4. 接收范围与访问审计

- 授予者视角分页（`GET /ai/report/share/page`）显示**接收范围**：接收者外部用户标识 +
  签发时刻的显示名快照（`grantee_display_name`，之后主体改名不改快照）。
- 访问审计（`GET /ai/report/share/access/list`）仅授予者本人可查（越权与不存在同语义 404），
  每次读取一条：访问者主体、结论（`GRANTED`/`DENIED`）、稳定原因码、是否真的出库内容。
  降级态是 `GRANTED` + `content_authorized=false`——"有人读取了但没拿到数字"这一事实必须可见。
- 审计行**不含**令牌摘要、报表规格与数据正文。

## 5. 明确不做（另立审批设计）

- **公开匿名链接**：不需要登录即可访问的分享会绕过"仅已登录且获授权主体之间分享"的边界，
  也无法绑定接收者主体；需要独立的安全评审（限流、滥用追踪、链接泄漏处置）与审批流，
  本卡不做。
- **固定快照分享（脱离源 ACL）**：把版本内容物化进分享行、读取时不再复核源权限的"离线快照"
  会让数据在授权回收后仍可读取，与 FR-28 的"读取/刷新仍按接收者当前源权限"冲突；
  如需此能力，必须作为独立需求另立审批设计并说明数据生命周期与保留策略，本卡不做。
- 分享给 APP 主体、跨应用分享、批量签发/改期：均不在本卡范围。
