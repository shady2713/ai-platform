# 评测夹具与期望规则边界（Q04）

评测的目标是"可复现地证明能力没有回退"，因此夹具、规则与报告都必须在**看不到任何真实客户数据**的前提下自证。
本文固定三件事：夹具来源、规则词表、报告边界。

## 1. 夹具来源与分级

- 样例的"问题"（`ai_eval_case.question`）必须是**合成问题**：合成系统、合成主体、合成金额与日期；
  不允许把生产问句、真实客户名或真实订单号复制进样例。
- 套件声明 `data_level`，只允许 `L1_PUBLIC` 或 `L2_INTERNAL`；服务层在创建时即拒绝更高分级
  （`AI_EVAL_DATA_LEVEL_NOT_ALLOWED`），因此执行器不会把 L3/L4 数据带进评测链路。
- 执行身份是套件登记的**合成主体**（`subject_type` + `external_user_id`，默认 `eval-runner`），
  不是真实用户；执行走与真实运行相同的运行服务与授权判定（同一服务、同一发布版本解析、同一模型端点）。

## 2. 期望规则词表（`ai_eval_case.checks_json`）

规则是 JSON 数组，每条一个断言；判定由程序完成，**模型评分不参与**（评分只能作为参考，不能替代断言）。
任何一条不合规（未知 `kind`、缺字段、类型不符、超上限）都会在**入库与冻结时**被拒绝（`AI_EVAL_CHECK_INVALID`），
不会等到执行时才把"规则写错"当成"样例通过"。

| kind | 字段 | 语义 |
|---|---|---|
| `MONEY` | `path`、`expected` | 金额按数值比较：两侧四舍五入到 2 位小数后相等即通过（`450` 与 `450.00` 等价；`290.005` → `290.01`） |
| `DATE` | `path`、`expected`、`zone`（可选，默认 UTC） | 只比较到天；纯日期字面量按字面比较，带偏移/时区的实际值按 `zone` 换算到天 |
| `VALUE` | `path`、`expected` | 精确相等：数字按数值比较，其它按文本比较 |
| `STRUCTURE` | `requiredPaths` | 这些路径全部存在且非 null |
| `CITATION` | `path`、`mustReferenceAnyOf` | 实际引用中至少一个来自允许集合（等值或前缀匹配，如 `kb:12:`） |
| `VERSION` | `path`、`expected` | 实际版本标识等于期望值（模型端点修订、服务发布版本等） |
| `NO_SECRET` | `path`（可选，缺省整份实际值） | 不得出现凭据/票据/连接串/密钥前缀；判定复用审计脱敏器并额外拒绝 `sk-`/`rk-`/`pk-` 形态 |

`path` 支持点号路径与数组下标（如 `result.rows[0].amount`）；不存在的路径按"缺失"处理（判定不通过），
不会当成 0 或空串。

## 3. 报告边界（AT-011 / AT-058 口径）

可复现报告（`GET /ai/eval/report`）与结果接口只输出：

- 运行快照：套件编号与修订、`suite_digest`、计数、起止时间；
- 逐例：`case_key`、级别、判定、期望/实际版本标识、稳定失败码、逐条核对结论（规则/期望/实际/说明）、
  `case_digest`、`result_digest`、复核状态与备注。

**不输出**：合成问题正文（只在样例接口里，且样例本身就是合成数据）、提示词模板、模型响应正文、
事件块正文、端点地址与任何凭据。模型输出若进入观测值，只以 `outputDigest`（SHA-256）形式参与摘要，
正文不出现在结果与报告里。

`case_digest` 冻结"样例期望"，`result_digest` 冻结"样例 + 实际事实 + 结论"；人工复核会改变最终判定，
因此同时重算 `result_digest`（复核前后摘要不同是**正确**表现，报告里两处都给出复核状态）。

## 4. 计数口径

`ai_eval_run` 的计数：`passed_count` 只计 `PASSED`；`FAILED` 与 `REVIEW_REQUIRED` 计入 `failed_count`
（后者待人工复核）；`ERROR` 计入 `error_count`；三者之和等于 `case_total`。
`ERROR` 表示**未能执行**（如没有可用发布版本或模型端点），必须带稳定失败码，且不得被记为通过。
