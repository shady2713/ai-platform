# 管理后台威胁模型

范围为浏览器管理端、Spring 应用、MySQL、Redis、文件存储及短信/对象存储等外部适配器。
增加开放 API、多租户、SSO 或富文本前必须先修订本文。

## 资产与信任边界

关键资产是 L4 凭证、L3 个人信息、权限与配置完整性、服务可用性和审计可信性。

1. 浏览器或网关到 Spring 应用；
2. 应用到 MySQL、Redis 和本地文件系统；
3. 应用到短信、对象存储等外部服务；
4. 管理员控制面到凭证、权限和任务能力。

## 威胁与控制

| # | 威胁 | 当前控制 | 必须保持的边界 |
|---|---|---|---|
| T1 | 爆破、撞库和账号枚举 | 登录、短信和重置入口按客户端 IP 限流；客户端 IP 解析默认 fail-closed（不采信代理头，只有 `basic-framework.web.trusted-proxies` 登记的直接对端才采信 `X-Forwarded-For`/`X-Real-IP`）；账号密码连续 5 次失败后锁定 15 分钟；未知手机号的短信发送与重置流程使用通用响应；未知或锁定账号执行部署强度的假哈希校验；成功密码登录按当前工作因子条件升级旧哈希 | IP 限流与账号锁定必须并存且存储异常时不得静默放行；代理头必须在可信代理边界之外不可伪造，未配置可信代理时不得以代理头替代真实客户端 IP；公开认证入口不得通过错误码、文案或是否执行密码哈希的时序差异泄露账号状态；哈希升级必须按认证时旧值条件更新，不能覆盖并发改密；管理员解锁必须鉴权并审计；不得增加自助注册 |
| T2 | Token 伪造、窃取和重放 | CSPRNG；数据库仅存会话摘要；MySQL 唯一权威和账号行锁拒绝已失效凭据签发；refresh Cookie 隔离并单次轮换；账号和权限变化撤销会话 | refresh token 不得作为 access token；原始 token 不得进入日志、管理页或持久层 |
| T3 | 越权和控制面接管 | 默认要求认证；Controller 声明权限；高风险命令服务端权限校验；新角色在 Service 与数据库层均默认 `SELF` 数据范围；应用表数据权限分类门禁；每张豁免表登记替代控制及生产源码证据；授权关系写入前校验目标状态；涉及 `super_admin` 的授予、撤销、菜单和数据范围变更在 Service 层校验操作者也持有启用中的 `super_admin`；受保护表强制装配身份提供器；精确集合测试防回退 | 新入口必须定性为公开、认证或专用权限；页面隐藏和 Controller 注解不能替代 Service 授权；新增角色不得因调用方漏传或绕过 ORM 自动获得全部数据范围；普通管理员不得创建、扩大、缩减或间接改变超级管理员能力；豁免不能只写理由，控制证据缺失或漂移必须阻断；受保护表不得因身份能力缺失或权限响应不完整而静默执行原 SQL |
| T4 | 路径穿越、恶意压缩包和文件泄露 | canonical path 边界；ZIP 条目数、展开量和压缩比限制；存储类型白名单；文件元数据的读取策略与所有者校验 | `/infra/file/{configId}/get/**` 只允许 `access_type=公开` 的对象匿名读取；私有对象必须匹配所有者或文件管理权限，未授权与不存在统一返回 404，不能以不可猜路径代替鉴权 |
| T5 | SQL、模板、命令和 XSS 注入 | MyBatis 参数化；排序 allowlist；统一 XSS cleaner；禁用富文本和动态脚本 | 不使用字符黑名单；动态查询只允许服务端固定的数据源和字段集合 |
| T6 | SSRF 与内网横向访问 | 文件适配器使用类型白名单；外部地址由受权限配置持有 | JDBC、回调和对象存储端点不能只做 URL 语法校验；部署层必须限制出站网络，新增主动抓取能力前实现统一目的地址策略 |
| T7 | 秘密或个人信息泄露 | 数据分级；敏感日志清理；L4 默认禁出；高风险配置读取要求专用权限 | 可恢复秘密必须 AES-GCM 存储；含秘密对象不得生成完整 `toString()` |
| T8 | XSS、CSRF、开放重定向与浏览器侧伪加密 | 无富文本；统一外链入口；登录后跳转仅接受管理后台本地绝对路由；refresh Cookie `SameSite=Strict`；浏览器端不保存解密私钥 | TLS 是传输保密边界；credentialed CORS 只能使用显式来源白名单；跳转参数按 [ADR 0016](../adr/0016-validate-local-login-redirects.md) 校验 |
| T9 | 供应链和凭证误提交 | Maven/pnpm 锁定版本；Gitleaks 全历史扫描；CycloneDX 聚合 SBOM 与 Trivy 扫描后端依赖、前端锁文件、容器配置和最终应用镜像 | HIGH/CRITICAL 漏洞必须阻断 CI；扫描器镜像须固定版本和摘要，输入仓库须只读挂载 |
| T10 | 任务重放 | Quartz JDBC JobStore | 立即执行必须鉴权并审计；作业副作用必须幂等 |

## 已知设计权衡

- 刷新令牌按 RFC 6819 单次轮换并启用重放检测：同一账号在两个浏览器标签页中并发刷新时，后到的请求被判定为重放并吊销整个刷新家族，该标签页被踢回登录页。这是防重放的预期代价而非漏洞；受影响标签页重新登录即可。
- 本人可在个人中心自助改绑手机号与邮箱，不要求旧密码或原手机号二次验证。管理后台威胁模型下账号会话本身即高权限凭据，持有者被视为本人；入侵后持久化风险由会话吊销、登录锁定与审计发现环节承担。

## 不接受的风险

- 公开创建后台账号；
- L4 正文出现在日志、异常响应、指标标签或管理列表；
- 用浏览器内置密钥、路径不可猜或前端按钮隐藏代替 TLS、鉴权或服务端授权；
- 文件访问越出配置根目录；
- 未验证归属的跨模块写入或未登记的数据生命周期关系。
