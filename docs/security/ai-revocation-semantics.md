# AI 中台撤销语义（A06）

本文定义"撤销应用 / 撤销主体"的保证范围与不保证的范围，是 A06 的契约性说明。

## 撤销命令覆盖的四条链路

| 链路 | 撤销后的行为 | 证据 |
|---|---|---|
| 应用状态 | 停用；`authenticate`（换票）与范围解析立即拒绝 | `AiRevocationServiceImpl#revokeApplication` |
| 资源授权 | 该应用（或该主体）名下**全部授权**置为 REVOKED，并逐条递增 `authz_revision` | 同上（分页遍历，逐条 CAS） |
| 访问票据 | 应用（或主体）名下**全部票据**置为 REVOKED | `AiTicketService#revokeTicketsOfApplication` / `#revokeTickets` |
| 会话与后续步骤 | MEMBER 会话校验每次都重新读状态，因此撤销后旧票据立即不可认证；执行上下文重建失败 → 受限步骤停止 | `AiUserSessionCommonApi`（A05）、`AiExecutionContextFactory`（A06） |

撤销在**一个事务**内完成：要么全部失效，要么都不变（不存在"只停用应用但票据仍可用"的中间态）。

## 明确不保证的部分

1. **已发送内容无法回收**：撤销前已经交给上游模型或外部系统的内容（提示词、检索片段、工具参数）
   已经离开平台，撤销不会、也无法召回这些副本。因此对外发等级的判定（M05）必须在**发送前**完成。
2. **已生成产物需要重新鉴权**：撤销后仍存在的历史产物（报表、聚合、文件）不会自动删除；
   读取前必须用 `reauthorizeHistorical(...)` 校验范围指纹（A03），指纹变化即拒绝。
3. **后续工具步骤**：已经启动的工具体系步骤必须在每一步开始前重建执行上下文（A06），
   撤销后重建失败即停止；平台不保证"正在执行中的单次上游调用"被中途打断（按超时收敛）。

## 到期清理

`AiTicketCleanupJob` 按批逻辑删除"已撤销或过期超过保留期（默认 24 小时）"的票据：

- 只处理已失效票据，不触碰任何仍可用于认证的票据；
- 幂等：重复执行不会产生额外副作用；
- 有界：单批条数与批次数都有上限，避免一次任务扫全表。

保留窗口内票据仍可对账（访问日志与运维排查），窗口外才删除。
