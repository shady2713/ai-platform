# 08 测试与验收规范

## 1. 证据层级

单元测试验证确定性规则；Controller测试验证HTTP/鉴权/输入；Testcontainers验证真实MySQL/Redis/索引与事务；打包jar冒烟验证装配；真实浏览器验证页面和跨域；固定模型评测验证AI理解；升级演练验证版本和数据恢复。任何一层不能用另一层的绿色代替。

测试范围以任务卡和下表为准。真实业务数据需另行授权，本包只定义合成夹具。

## 4. 模型评测的可复现性

记录模型提供商、modelId/digest（可得时）、温度等参数、服务release、prompt、schema、数据夹具、测试时钟和评测版本。确定性编译/权限测试不调用真实模型；理解与引用测试另跑冻结模型，避免拿mock证明AI效果。

首期建议至少60条明确问题及20条歧义/越权/提示注入问题。明确问题覆盖API、SQL、知识、报表修改；按PRD阈值统计意图与结果。只重跑失败样例不能替代最终完整固定集。

## 5. 性能与稳定性

先记录机器、数据库索引、模型/接口Mock延迟、数据规模；测平台受理/查询/流处理开销，再单独记录真实模型端到端耗时。至少覆盖20并发run、慢模型、慢API、文件索引并发、取消风暴和客户端断线。

记录P50/P95/P99、错误率、队列、连接池、内存、CPU、索引耗时和GC。满足阈值才通过，硬件不符时结论标不可比。不能承诺任意规模业务数据库都在固定秒数内响应。
