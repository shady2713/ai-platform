## 3. 逐步实施

1. **复用现有装置**，不要另起炉灶：`playwright.config.ts`、`fixtures/chart-probe/`
   （`global-setup.mjs` 构建探针 + `server.mjs` 静态服务 + `page.html` 挂载点）与
   `support/workspace.ts` 都在。Y06 扩面时只给 `entry.ts` 加了一个 `mountResultTable` 桥接，
   沿用同一手法即可。
2. **按"安全语义优先"排序**补用例。首批目标（页面存在且有组件测试）：
   - `semantic`（Y02 主数据映射 / Y07 跨源契约）——**最高优先**：授权拒绝时界面确实不暴露数字
   - `authorization`（Y05 授权矩阵）——失权/撤销后的渲染
   - `report`（R07 报表页 + Y06 已有的表格/WITHHELD 对照）
   - `dataset` / `model-endpoint` / `connector`（配置面：只读字段不可编辑、状态可见）
3. 每条用例都要有**对照**：证明断言不是恒真（Y06 的"整包 vs 增量"、"渲染 vs WITHHELD 不出数字"
   就是这个模式）。

## 4. 验收与失败分支

- **真实 Chromium**（本地 `~/.cache/ms-playwright/chromium-*`），不是 jsdom/happy-dom
- 每条用例断言**可观测的结构事实**：元素出没、文案逐位、行数、列数、控件可用性
- **不做**：像素级视觉回归（ADR 0046 决策 2）、需要真实凭据/真实平台（48080）才能跑的联调、
  没有页面的空验收
- 失败路径必须钉住**稳定错误文案/状态**，不得只断言"抛了异常"
- **不得为了让它变绿**而放宽断言、跳过用例或加 `retries`

**反向用例是本卡的价值所在**：至少覆盖
- 授权被拒时，**界面确实不出现**被禁明细/合计（Y05 语义）
- `WITHHELD` 时一个数字都不渲染，而 `COMPLETE` 时照常渲染（Y07 契约）
