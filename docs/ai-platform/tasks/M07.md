## 1. 任务目标与输入

**补一个安全语义缺口。** M02 交付的模型客户端目前**只有创建期的出站治理，没有请求期的**：

`SpringAiModelClientFactory.createClient`（`:112-115`）这样构造客户端：

```java
OpenAiApi openAiApi = OpenAiApi.builder()
        .baseUrl(snapshot.baseUrl())
        .apiKey(snapshot.apiKey())
        .build();
```

**没有任何 HTTP 客户端定制**，因此走 Spring AI 默认的 RestClient/WebClient。
结果是：端点快照在**创建期**校验过出站允许清单、解析层也会拒绝已停用端点，
但**每一个实际发出的请求**并不再过 F09 的守卫。

F09 已交付的 `GuardedExternalHttpClient`（`core/http/`，251 行）实现了平台抽象
`ExternalHttpClient.execute(ExternalHttpRequest)`；M02 的证据文档
（`verification/m02-*.md` 未验证项第 1 条）已把"请求级传输治理尚未接入"登记为已知缺口。

## 3. 逐步实施

1. **确认 Spring AI 1.1.8 的接线点**。用 `javap` 实测 `OpenAiApi.Builder` 有哪些
   客户端定制方法（`webClientBuilder` / `restClientBuilder` / `clientBuilder` 等），
   **不要凭记忆写**。同时确认 `OpenAiChatModel` / `OpenAiEmbeddingModel` /
   转写 / 语音四条通道各自用哪个客户端——它们可能不一样。
2. **写适配器**把 Spring AI 的实际请求桥接到 `GuardedExternalHttpClient.execute`，
   使**每一个出站请求**都过守卫。四条通道都要覆盖，不得只做聊天通道。
3. **证明请求期治理真的生效**：出站到非允许清单地址的请求在**请求期**被拒，
   且该拒绝能被稳定错误码表达——这是本卡的核心验收，不是"配置看起来接上了"。

## 4. 验收与失败分支

- **AT-070** 相关的出站安全条款（详见[验收目录](../08-testing-acceptance.md)）
- **出站到非允许清单地址在请求期被拒**（反向用例，不能只测创建期）
- **四条通道都经守卫**（聊天/嵌入/转写/语音逐条断言，不允许"其余同上"）
- **守卫拒绝时给出稳定错误码**，不泄漏上游响应内容
- 端点已停用、超时、5xx 重试的行为与现状**不回退**（M02 已有用例不得削弱）

**专项必须用反向测试。** "守卫接上了"只能靠**构造一个会被守卫拒绝的请求**来证明；
只跑正常路径等于没做本卡。

## 5. 必须产出

- 请求级出站治理的接线与四条通道的一致性证据
- 拒绝路径的稳定错误码与审计留痕
- 未接入的通道（若确有）必须在证据里逐条列明，不得笼统写"部分通道"

- 测试使用真实 MySQL/Redis Testcontainers 或 JUnit/Mockito；**不得新建 H2 测试**。
- **任何源文件（含测试）≤ 800 行。** `SpringAiModelClientFactory.java` 已接近上限，
  适配器**必须另起文件**，不要往现有类里堆。
- **契约台账的 `version` 字段不得改动**：`data-lifecycle.json` 必须为 `1`、
  `data-permission-exemptions.json` 必须为 `3`。
