## 3. 逐步实施

先列出本卡实际要创建/修改的文件、对外方法和验收用例，然后按顺序实施：

1. **把 Y05 的判定结论产出为响应契约字段**：跨源合并响应恒携带完整性口径。
   缺失即按 `WITHHELD` 处理，**绝不按 `COMPLETE` 渲染**——凭空替后端宣布"你有权看"
   与 Y05 的 fail-closed 原则直接冲突。
2. **补跨源合并的对外 HTTP 入口与鉴权**：复用 Y05 的守卫与 Y04 的执行台账，
   **不另起授权口径**。每个端点恰好一个 `@PreAuthorize`，权限码随迁移种子进目录。
3. **让前端完整性展示对真实后端数据生效**，并对单系统响应保持零影响。

每一步完成后编译或运行相应 focused 测试；共享接口先由契约确定，禁止消费者各自猜字段。

## 4. 验收与失败分支

- **AT-071**
- 跨源响应恒带完整性口径；**字段缺失视为 `WITHHELD` 而非 `COMPLETE`**
- 无权来源在响应中不可反推明细（差额可解、条数可数均不成立）
- **单系统响应与旧行为逐字段无差异**（反向：不许因为新增字段让单系统报表变形）
- 权限提示不能提权、撤销后立即不可读（继承 Y05 语义，不得削弱）

关联验收用例详见[验收目录](../08-testing-acceptance.md)。本卡未列编号的专项测试同样是完成条件。

**专项必须是反向测试。** "字段缺失时按 WITHHELD"这一条只能靠构造一个**故意不带该字段的
跨源响应**来证明；只跑正常路径等于没做这条验收。

## 6. 工程约束

- 不得修改只读源框架；路径均相对另行授权的工作副本。
- **先检查依赖任务的测试证据与公开契约**（Y04/Y05/Y06 三份），禁止用临时 stub 冒充依赖完成。
- 公开契约变更先改权威 Schema 和样例再改消费者，不能降低校验或覆盖率基线。
- **构造器注入**；Controller VO 只属于协议层；Service/DAL 不反向导入 VO；跨模块只用公开 CommonApi/DTO。
- 测试使用真实 MySQL/Redis Testcontainers 或 JUnit/Mockito；**不得新建 H2 测试**绕过真实约束。
- 复用 Vue/TypeScript 工作区、请求和反馈规范；禁止新增显式 any、v-html、innerHTML 和任意脚本渲染。
- 新增 typed 包必须有真实 typecheck、coverage 与 build，并验证加载/空/失败/失权/销毁状态。
- **契约台账的 `version` 字段由各自校验器定义，不得随手升号**：
  `data-lifecycle.json` 必须为 `1`，`data-permission-exemptions.json` 必须为 `3`。
  升版本号会直接让 `contracts` 门禁红。
- 任何源文件（含测试）**≤ 800 行**。
