# 09 给后续编码模型的执行手册

## 1. 目标

将工作拆成可独立验证的小任务，减少隐含设计决定。模型不需要根据聊天记录重新发明产品；使用本包的需求、协议、依赖和任务卡。

## 2. 每次会话的启动提示

```text
你负责企业AI中台的一个开发任务。
任务ID：<从tasks/index.json选择READY任务>
允许写入的工作副本绝对路径：<用户明确授权的路径>
源框架 E:\kuangjia\2026-main 只读，不得写入或在其中运行构建。

先读工作副本最近的AGENTS.md、.harness规则、docs/development-guide.md，
再读文档包README、01、任务卡列出的输入以及相关契约。
列出本任务依赖的完成证据和允许修改的文件。
只做当前任务，不追加功能，不替换技术栈，不复制上游整个平台。
任务涉及权限、凭据或认证等高风险实现时，核对用户对该范围的明确授权。
按步骤实现并运行真实检查；不能用删除测试、降低覆盖率或放宽安全规则通过。
完成时按本文件交接模板返回。缺少验证只能报告未验证，不能写已完成。
```

## 3. 先确认事实，后改代码

1. 检查当前Git diff，保留已有用户修改。
2. 用rg定位目标代码和最近规则；核实基线与本包有无漂移。
3. 读取依赖任务证据；只有类或接口存在不足以证明完成。
4. 按实际路径展开任务卡别名；禁止把尖括号占位符原样写进源码。
5. 提出本任务3–6步实施顺序和预期检查，再执行。

## 4. 强制禁止

- 不得写入原框架，不得擅自创建部署、提交、推送、PR或外部消息。
- 不得把系统管理用户当成业务系统用户；不得用ADMIN token处理开放API。
- 不得跨模块直接引用infra FileService、system Mapper/Service、其他模块DO。
- 不得自动执行模型返回的原始SQL、HTML、JavaScript、Shell或任意工具。
- 不得给app接口加全局PermitAll、给文件读取伪造管理权限、取消检索ACL。
- 不得把Spring AI/GPT-Vis类型暴露到本平台公开API和长期存储协议。
- 不得新增字段注入、显式any、手写分散校验规则、直接ElMessage或v-html。
- 不得在日志输出token、密钥、数据库连接串、模型输入正文或原始异常消息。
- 不得修改已执行Flyway、覆盖锁文件为浮动latest、关闭安全扫描、忽略失败测试。
- 不得留下假实现、空按钮、恒成功mock或未验证功能当作产品交付。

## 5. 需要暂停当前任务的条件

没有授权写入副本；高风险实现没有相应明确授权；任务依赖缺证据；核心契约冲突；选定上游版本无法安全兼容；数据权限策略不可执行；实际修改范围显著超出卡片；测试环境缺失导致关键边界无法验证。

暂停时报告具体阻塞、已完成内容、可继续的独立部分以及一个最小需要决策的问题。环境等待不是测试通过。

## 7. 评审提示模板

```text
只评审任务<id>的diff与验收证据。
逐项核对：范围、框架规范、公开契约、权限/秘密、状态与并发、

不要用格式化偏好制造无关改动；不要仅凭编译通过批准。
```

## 8. 任务状态管理

PLANNED → READY → IN_PROGRESS → REVIEW → VERIFIED → DONE；失败可BLOCKED。本包初始不维护实际实施运行状态，后续在用户选定的任务系统或工作记录中维护；不要把运行状态写进.harness。生成卡片的JSON是规划事实源，不是自动批准流水线。
