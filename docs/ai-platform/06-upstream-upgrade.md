# 06 上游集成、升级和回退策略

## 1. 原则：稳定契约包住变化

本产品自身代码遵守框架AGENTS、分层、命名、测试和门禁。第三方发布包保持原样，通过适配器调用；不把vendor源码整份复制、改名、重排格式后混入业务模块。

每个集成对象分为四层：上游发布包 → 自有适配器 → 自有业务契约 → 产品功能。上游类型、数据库结构和认证体系止于适配层。接口、QueryPlan、ReportSpec、权限和数据生命周期由本产品拥有。

## 2. 三类升级分别管理

| 类别 | 例子 | 升级单位 |
|---|---|---|
| 代码依赖 | Spring AI、GPT-Vis/G2、Tika、JDBC | BOM/catalog/锁文件+适配器+回归集 |
| 外部运行服务 | 模型API、Ollama、Qdrant | 服务版本/镜像digest+协议能力+数据格式 |
| 基础框架 | 用户的2026-main后续提交 | 基础框架版本差异+扩展接缝+完整Harness |

模型权重、提示词、嵌入模型和数据口径变化即使没有代码升级，也需要相应的质量回归。

## 3. 接入台账

在实施仓库维护 `docs/integrations/upstream-registry.yaml`（当前本包仅提供规划样例）。每个条目必须含：

- componentId、用途、官网/仓库、许可证文件与NOTICE来源。
- 当前选定版本、commit/tag、包integrity或镜像digest；`latest/main/SNAPSHOT`不能作为生产锁定值。
- 适配器目录和业务契约、负责人角色、依赖的Java/Boot/Node版本。
- 兼容测试清单、安全公告入口、升级触发条件、是否含数据迁移。
- 本地补丁记录、上游issue/PR（如有）、替代路径、退出条件。
- 回退所需旧包、旧镜像、旧索引、备份和有效时间窗。

台账中unknown/pending明确阻止依赖冻结任务完成；不能填伪造hash、镜像digest或“已兼容”。

## 4. 各组件的集成与更新方式

### 4.1 Spring AI

只在AI starter的provider/springai中引用其类。使用框架dependencies BOM集中管理，业务POM不各自写版本；第三方BOM不能静默把项目Boot、Jackson、Netty、gRPC、MyBatis依赖降级或升级。

初始候选1.1.7有官方发布和Java17/Boot3.5的POM证据；这是兼容实验起点，不代表2026-09最新或可免漏洞扫描。实施时重新查询维护状态、补丁与安全公告；若该分支缺乏需要的维护，提出受支持替代适配/基础框架升级的独立决策，禁止静默切Boot4。

升级回归：多端点凭据隔离、文本流、工具调用参数、结构化输出、嵌入维度、错误与取消、usage、超时、受限过滤、数据库/日志无泄漏。用同一固定问题集对比输出表现。

Spring AI 2.x官方文档要求Boot4系列，因此作为单独平台升级项目评审。Spring AI Alibaba按需添加，不能为了agent示例引入Graph、控制台、网关等整套依赖。其公开兼容表的1.1.2组合不能覆盖本产品的安全版本准入。

### 4.2 AntV

通过pnpm包固定版本和锁文件integrity；应用只调用ChartRenderer。保存的是自有ChartSpec/ReportSpec，而不是GPT-Vis内部实例/DSL。

升级回归：首期图表固定样例、数据精度、null/空集、大数据限制、深浅色、窄容器、resize/destroy、主题切换、旧报表、严格CSP、恶意标题/URL、包体预算。图表出错需保留可读表格和明确提示。

GPT-Vis默认导入可能包含多个图表依赖；P0必须测真实产物而非引用“支持tree-shaking”就通过。若不达标，以相同适配接口采用G2受控图表实现，并记录唯一默认路径。

不通过公共CDN加载未固定版本。AVA作为设计参考不纳入运行依赖；若日后引入其代码执行或Node服务，需新架构、安全、部署与生命周期评审。AntV MCP图片服务默认远程渲染不作为本平台私有化默认通道。

### 4.3 Qdrant与索引

启用前记录服务端版本、Java客户端、Spring AI适配器以及过滤协议的兼容结果。当前Spring AI候选POM内的Qdrant客户端版本不能推导与最新Qdrant服务器兼容，必须做组合验证。

升级前：暂停或隔离索引写入、记录水位、保存MySQL文档/ACL版本、集合配置、别名和快照，保留可重放入库任务。

升级按官方相邻小版本规则逐段进行，不能跨多个小版本直接跳。单节点需要维护窗口，不承诺零停机。旧快照可恢复的目标版本按官方约束核实。

**禁止用旧镜像直接挂载已升级的数据目录回退。**需要回退时，启动旧版本独立实例，从升级前兼容快照恢复，重放明确记录的入库变更；或切回仍保留的旧集合/实例。向量索引变更不能覆盖MySQL当前ACL。

官方资料：[升级](https://qdrant.tech/documentation/upgrades/)、[快照](https://qdrant.tech/documentation/operations/snapshots/)、[不支持直接降级说明](https://qdrant.tech/documentation/faq/)。

### 4.4 模型API/Ollama

provider协议、实际模型版本、能力探测和提示词版本一起入账。兼容API通常只有部分能力；每次服务端升级重测TEXT/EMBEDDING/TOOLS/STRUCTURED_OUTPUT及已启用媒体能力。

同名模型更新不能视为无变化。企业能够提供模型digest时记录digest，否则记录供应商版本、探测时间和不可复现限制。先复制端点配置为候选revision，跑评测后切服务发布版本；旧run仍记录原revision。

默认不在故障时把企业数据转发到其他模型平台。回退需要旧模型确实仍可调用，不能仅把数据库modelId字符串改回去就声称恢复。

### 4.5 Tika/解析器/JDBC

沿用集中版本；增加解析器需扫描传递依赖与许可证。升级用真实PDF/DOCX/中文/表格/损坏文件/压缩炸弹边界夹具回归。解析结果变化会影响切片与索引，不能在后台无提示地全量覆盖。

JDBC升级验证TLS、时区、DECIMAL、字符集、只读连接、取消/超时、连接池关闭、metadata返回。禁止通过关闭TLS验证或放宽序列化设置消除测试失败。

## 5. 自有代码与上游补丁

优先级：公开配置 → 公开扩展点 → 自有适配器 → 最小有期限补丁。

确需fork/patch时记录patchId、上游基线、修改文件、原因、对应失败测试、许可证保留、重放命令、移除条件和责任人。补丁目录与业务实现分开，禁止手改node_modules或本地Maven缓存；不能只提交最终vendor目录而丢失差异来源。

上游已修复时，用原始发布包替换补丁并重跑回归后移除。向上游提issue/PR属于外部写入，需用户另行授权；本方案不授权自动提交。

第三方源码不强制改成项目代码风格；本平台新增/修改的适配代码完全遵循项目标准。依赖自身测试不能替代本产品集成测试。

## 6. 用户基础框架更新

本项目用`framework-baseline-23a7edb37593`标签和`docs/framework-baseline.json`保存首次原框架基线，具体Git关系见[00](00-project-bootstrap.md)。后续基线升级创建新标签，保留旧标签；记录当前HEAD与本产品所改核心接缝。日常AI业务修改集中在新增模块及声明的扩展位置。

每次同步：

1. 读取新框架AGENTS、ADR、依赖和迁移差异；先判断代码要求是否变化。
2. 对比认证、文件、Web、数据权限、字段/生命周期契约及Harness变化。
3. 在隔离升级分支/工作副本试合并，保留框架安全修复；冲突逐项记录，禁止用ours/theirs整片覆盖。
4. 检查迁移版本碰撞。仅尚未发布的迁移允许重编号；已执行迁移内容与编号冻结，按新ADR规划后续迁移。
5. 对照上游删除的能力，确认AI依赖是否仍合法；不通过恢复已删除死代码维持编译。
6. 运行完整Harness、开放身份、文件权限、Chat、RAG、报表与升级回归。
7. 更新framework-base、核心接缝差异台账、发布说明和回退材料。

如果用户框架未提供稳定tag，commit仍可作为可复现基线，但不能声称有外部兼容承诺。原路径保持只读；同步在授权副本进行。

## 7. 标准升级流程

| 步骤 | 输出 | 通过标准 |
|---|---|---|
| U1 发现与分类 | 版本/安全公告/维护状态差异 | 区分安全补丁、兼容小改、破坏性、存储格式变化 |
| U2 影响分析 | 适配器、协议、数据、UI和任务影响表 | 找到所有直接与传递消费者 |
| U3 备份与回退设计 | 旧包/镜像/配置/数据/索引材料 | 实际验证可恢复，不只有备份命令 |
| U4 升级分支 | BOM/catalog/lock/SBOM/必要适配diff | 不含无关重构，未降低门禁 |
| U5 自动回归 | Harness、合同、golden、浏览器、安全结果 | 必需测试全部通过，无越权与泄漏 |
| U6 行为对比 | 模型质量/中文检索/图表/性能差异 | 变化可解释且满足PRD阈值 |
| U7 预发布演练 | 新装、升级、N-1 SDK、回退报告 | 对客户复制环境有效 |
| U8 发布审批 | 具体版本、影响、维护窗口、回退点 | 用户批准具体发布动作 |
| U9 发布后观察 | 指标、错误与已知限制 | 超阈值触发已演练的回退/修复流程 |

建议按月检查常规更新，安全公告及时评估；这只是运维流程，不在本次创建任何定时自动化或外部通知。

## 8. 兼容策略

- 外部API与SDK支持N/N-1，升级测试使用真正的旧SDK产物，不用新源码切一个常量模拟。首次发布没有历史N-1时，冻结首发候选产物与Schema样例；本轮仅报告基线兼容验证，首次升级开始使用已发布旧产物。
- 自有ReportSpec/QueryPlan带schemaVersion；结构变更有显式迁移器、输入夹具和回退影响。
- 服务发布版本、模型配置版本、语义版本独立；运行记录可还原所用组合。
- 嵌入模型/切片算法改变创建新index generation，全量构建并评测后切换，保留旧generation用于回退；不同向量空间不能混写。
- 数据库先加字段/表，兼容读写，迁移数据，经过窗口再收缩。应用二进制回退不能假装回滚已执行Flyway。
- 回退的数据损失窗口必须说明；已发生的业务写入不可通过回退代码撤销，应走业务补偿/核对。

## 9. 发布物清单

server jar/image、admin/chat静态资源、版本化SDK、开放API规范、协议Schema、Flyway迁移和快照、SBOM、LICENSE/NOTICE、上游注册表、配置模板（无秘密）、备份恢复手册、变更说明、兼容矩阵、测试证据摘要、已知限制。

只有这些材料与实际构建版本对应，才可标记升级包可供部署；本次文档包不代表任何组件已经集成或生产可用。
