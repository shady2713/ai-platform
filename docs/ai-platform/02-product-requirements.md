# 02 产品需求文档（PRD）

## 1. 产品目标

在现有 Java/Vue 框架内建立企业 AI 能力平台。企业业务系统通过统一 API 或可嵌入 Chat 使用模型、知识、数据分析、报表和工具能力。企业在独立部署内配置自己的模型与业务资源，平台提供可复用机制。

核心价值：业务系统统一接入；用户自然语言完成授权范围内的查询与分析；结果可追溯；接入与升级可维护。

## 2. 已确定需求与设计默认

### 2.1 用户已确定（C）

| 编号 | 已确定内容 |
|---|---|
| C01 | 基于现有框架；当前原框架目录严格只读 |
| C02 | 向多家企业交付，每家独立部署 |
| C03 | 产品定位是服务业务系统的能力中台 |
| C04 | 模型在外部部署，中台主要管理模型 API |
| C05 | 业务系统的 AI 请求统一通过中台 |
| C06 | 同时提供 API 和可集成的 Chat 页面 |
| C07 | Chat 默认覆盖当前业务系统，页面内容可作辅助上下文 |
| C08 | API 和数据库都要接入 |
| C09 | 需要自然语言查询、数据分析、图表和 Web 报表 |
| C10 | 报表支持即时使用和保存后再次使用 |
| C11 | 产品包含知识、图像、语音能力，多模态受模型能力约束 |
| C12 | 业务与研发协作；操作可配置自动、人工确认、禁止 |
| C13 | 一期先接一个业务系统；跨系统后续迭代；质量和维护成本优先 |

### 2.2 本包用于实施拆分的设计默认

采用单体模块化后端、首期结构化查询计划、受控 ReportSpec、独立 Chat 前端与 iframe SDK、Spring AI 适配和 AntV 渲染适配。具体见 [决策台账](10-decisions-sources.md)。这些是可评审建议，不冒充用户已确认的技术细节。

## 3. 角色与工作流

| 角色 | 工作内容 | 权限边界 |
|---|---|---|
| 平台管理员 | 应用、模型、凭据、资源授权、配额、部署配置 | 控制面角色不自动获得所有业务文档正文 |
| 应用接入研发 | 注册接口、接入 SDK/API、配置可信身份衔接 | 仅管理分配的应用；不能提升应用的授权上限 |
| 业务配置人员 | 维护术语、口径、服务提示词、知识资料、标准问题 | 无明文密钥读取权；发布权限独立分配 |
| 业务使用者 | 对话、查询、生成/修改/保存报表 | 受应用授权与个人数据范围共同约束 |
| 质量/运维人员 | 评测、故障排查、用量、升级与恢复 | 默认查看脱敏元数据，原文访问单独授权并审计 |

典型配置流程：注册应用 → 接入模型 → 接入知识/数据/API → 配置语义和授权 → 创建服务草稿 → 调试及评测 → 发布 → 获取 API/SDK 接入说明。

典型使用流程：业务后端换票 → Chat/API 发起问题 → 必要澄清 → 查询/检索/工具执行 → 结构化结果 → 报表预览 → 对话修改 → 保存或刷新。

## 4. 范围与交付版本

| 版本 | 目标 | 包含范围 |
|---|---|---|
| P0 验证关口 | 证明关键依赖和框架扩展可行 | 版本兼容、身份接缝、文件契约、图表及向量检索实验；只在授权副本开展 |
| V1.0 单系统闭环 | 一个业务系统真实可用 | 文本模型、应用/身份/授权、服务发布、开放 API、Chat/主题、知识问答、API 数据接入、MySQL 只读数据接入、结构化分析、报表、监控、质量与升级演练 |
| V1.1 能力增强 | 在单系统稳定基础上扩展 | 图片/OCR/生成编辑、STT/TTS、受控写工具、复杂报表导出和更丰富检索 |
| V1.2 扩展交互 | 复杂交互与生态接入 | 实时语音、MCP 客户端、可视化流程编辑器、组件级 Chat 集成；分别过验证关口 |
| V2 跨系统 | 多系统关联分析 | 多应用独立接入、对象映射、口径与粒度治理、跨源执行和权限 |

分期为本包的排期建议。所有产品能力保留，未列入 V1.0 的能力不得用空页面、假按钮或恒成功接口冒充交付。V1.0 只优先交付 MySQL 外部连接器；Oracle、SQL Server 等作为同一接口下的后续连接器，不在首期承诺兼容。

## 5. 功能需求

下列 FR 编号是追踪标识，任务卡和测试必须引用；一条需求可以由多张任务卡共同交付。

### 5.1 模型中心

**FR-01 模型端点管理（V1.0）**

- 页面：模型列表、创建/编辑、连接测试、启停、凭据轮换。字段：名称、provider 类型、baseUrl、上游 modelId、网络域策略、超时策略、secretConfigured、能力列表。
- 明文密钥只接受写入，不在查询、错误或调试记录中回显。使用中端点不能物理删除；先停用并解除引用。
- 测试连接是实际受限请求，结果包括时间、能力探测项、脱敏错误码。启用状态不等于质量合格。
- 验收：同一 provider 两套不同端点与密钥并发调用不串线；轮换只影响目标配置；停用后新 run 拒绝。

**FR-02 能力与模型选择（V1.0 基础，后续扩充）**

- 按 TEXT、EMBEDDING、VISION、IMAGE_GENERATION、IMAGE_EDIT、STT、TTS、REALTIME 声明能力。
- 模型支持、适配器支持、当前部署启用三项同时满足才能发布对应服务。OpenAI 兼容声明不能代替能力实测。
- 不匹配时发布失败并指出缺少的能力；不将不支持的模型参数透传后再让业务系统猜测。

### 5.2 应用、身份与授权

**FR-03 应用与凭证（V1.0）**

- 应用字段：appCode、名称、负责人、状态、允许嵌入 Origin、服务授权、资源授权、限额。
- 独立创建、启用、停用、轮换和吊销命令；应用密钥一次显示、仅后端保存。普通修改不隐式重置密钥。
- 应用停用后，token、会话运行、附件读取和报表刷新均拒绝新访问。

**FR-04 外部主体与会话（V1.0）**

- 支持应用自身 APP 主体和应用内 USER 主体，二者能力范围明确区分。
- 可信业务后端完成用户身份断言；中台为 `(appId, externalUserId)` 建内部主体。前端传 userId、部门、角色不直接形成授权。
- Chat 使用短期、可撤销凭证；登出、主体停用和应用撤销后失效。后台 ADMIN token 不能调用应用 API，应用 token 不能访问管理后台。

**FR-05 资源授权（V1.0）**

- 应用授权上限、服务资源绑定、当前用户 ACL 三者求交；请求指定资源只能缩小范围。
- 资源类型包括知识库/文档、数据集、工具、文件、会话和报表。无显式授权默认拒绝。
- 检索与执行前判定，历史结果和原文下载再判定；后台菜单隐藏不替代后端校验。

### 5.3 AI 服务管理

**FR-06 服务配置（V1.0）**

- 草稿字段：名称、serviceCode、模型、提示词、输入 Schema、输出类别、知识库、数据集、工具、执行上限、默认主题引用。
- 提供测试区：使用测试主体和固定数据验证，展示用户可理解的执行摘要、来源、耗时及结果；不展示隐藏推理链。
- 提示词中的业务说明不能授予权限，不能覆盖禁止工具、数据范围及输出协议。

**FR-07 发布与版本（V1.0）**

- 草稿可编辑，发布版本不可原地修改；发布前校验模型能力、资源有效性、必填字段、评测结果。
- 应用绑定发布别名；新 run 解析到明确 releaseId，后续消息沿用会话版本；升级会话需要显式新建或迁移。
- 回退切换发布别名，仅影响后续运行；资源授权和停用状态始终检查当前值，旧 release 不保留旧权限。

### 5.4 开放 API 平台

**FR-08 API 目录与接入文档（V1.0）**

- 单独展示开放能力、认证方式、版本、请求/响应、错误、流式事件、限额、Java/JS 调用示例。
- 区分应用访问凭证和最终用户凭证；知识写入、报告读取等 scope 单独授权。
- API 文档从实现契约生成并校验漂移；公开文档不得泄露内部地址、凭证或未授权管理接口。

**FR-09 统一运行入口（V1.0）**

- 输入 serviceId、conversationId（可选）、用户消息、附件引用、业务上下文及 requestId。
- 返回 runId、状态、结构化结果、引用、数据完整性、模型与服务版本、耗时。表格金额保留精确十进制。
- 同应用、主体、接口、幂等键相同且输入相同返回同一次运行；相同键不同输入返回冲突。

**FR-10 流式返回与取消（V1.0）**

- 支持消息增量、阶段状态、结构化块完成、待确认、完成、失败和取消。
- 在开流前完成认证和请求校验；开流后的错误使用明确事件。客户端按 seq 去重，不把断线当成功。
- 支持显式取消和断线查询最终状态；流恢复不重新触发模型或业务副作用。

**FR-11 异步任务（V1.0）**

- 文档入库和耗时报表使用持久任务；支持进度、失败原因、有限重试、人工重试、取消。
- 进程重启后可发现过期租约并恢复可重试工作；对不确定完成的外部写操作转人工核对。
- V1.0 以查询任务状态为基本集成方式；Webhook 在后续任务中交付，不提前暴露空接口。

### 5.5 Chat 与第三方 UI

**FR-12 会话与结果（V1.0）**

- 会话列表、新建、重命名、删除、消息发送、取消、错误重试、附件、引用、图表和报表卡片。
- 会话属于应用与主体；默认私人会话。重新生成保留原消息版本并产生新的 run，不篡改历史。
- 多轮问题可引用先前结果，但已撤销的数据不能再次进入模型上下文。

**FR-13 业务上下文（V1.0）**

- 宿主可传 page、objectType、objectId、filters、locale、timezone；只接受已注册 schema。
- 当前页面作为辅助信息，助手默认覆盖当前业务系统；上下文不改变用户权限。
- objectId 不存在或含糊时追问；上下文更新影响下一次 run，不修改在执行 run。

**FR-14 嵌入与 SDK（V1.0）**

- 同一 Chat 支持内嵌、侧栏、弹窗、独立页；SDK 提供 mount/open/close/updateContext/updateTheme/destroy。
- 提供 plain HTML 宿主和 Vue 宿主示例，测试跨 Origin。卸载清理监听器、连接和内存 token。
- 不依赖第三方 Cookie；凭证由宿主后端回调获取，经精确 Origin 握手交给 iframe。

**FR-15 主题与体验（V1.0）**

- 按应用配置品牌、色板、字体族白名单、字号档位、圆角、密度、深浅色、布局与功能可见性。
- 交互协议统一，视觉适配宿主；主题同样作用于表格、图表、报表。配置预览并版本化发布。
- 不接受任意 CSS/JS、远程字体脚本或模板表达式；键盘可操作、焦点可见、侧栏关闭后焦点回到入口。
- 必须处理加载、空、错误、超时、失去权限、模型不可用、长内容、窄容器和页面卸载。

### 5.6 知识库

**FR-16 知识库配置（V1.0）**

- 共享知识库和应用专用知识库；共享是显式授权，一份资源统一维护。
- 字段：名称、说明、所有者、嵌入模型/索引版本、允许应用、管理者、状态、保留策略。
- 服务绑定多个已获授权知识库；普通使用者不能修改绑定或扩大检索范围。

**FR-17 文档入库（V1.0）**

- 首期支持 TXT、Markdown、文本型 PDF、DOCX；扫描 PDF 转 OCR 属后续能力，明确提示。
- 状态可见：上传、排队、解析、切分、向量化、可用、失败、删除中；失败提供脱敏原因与重试。
- 文件指纹和外部 sourceKey 防重复；更新生成新文档版本，索引成功后再切换 activeVersion，失败保留旧可用版本。
- 支持受授权 API 文档同步；平台不隐式抓取第三方站点。

**FR-18 文档权限与生命周期（V1.0）**

- 库权限和文档 ACL 共同生效；检索前过滤、模型使用前复核、引用读取再鉴权。
- 撤销/删除立即关闭检索可见性；后台清理向量、切片、缓存和原文件引用，有失败补偿。
- 共用文件只在最后一个合法引用释放后回收。历史会话不得返回已失权的原文片段。

**FR-19 检索问答与引用（V1.0）**

- 问题检索相关切片，回答附文档/版本/页码或片段位置，点击引用按当前权限读取。
- 无足够证据时明确说明；引用必须对应实际检索片段，不能由模型编造文档 ID。
- 文档内容视作不可信数据，文档内“忽略权限”“调用某工具”等指令不能变成系统操作。

### 5.7 业务数据与自然语言分析

**FR-20 业务 API 连接器（V1.0）**

- 手工配置或导入限定范围的 OpenAPI 描述草稿；人工选择启用 operation，不自动公开整份接口。
- 配置方法、固定 baseUrl/path 模板、参数 schema、凭据引用、分页、字段提取、超时、限额和只读性质。
- 参数映射为声明式表达，禁止执行脚本；统计必须知道分页是否完整、是否截断和数据时间。

**FR-21 数据库连接器（V1.0）**

- 首期 MySQL 8 只读账号；连接池与平台业务库独立；只发现授权 schema/table/view，样本读取默认关闭。
- 运维配置网络允许范围；密码通过 CredentialCipher；不把外部库挂到平台默认 MyBatis 动态路由。
- 连通成功后登记允许的数据集；仅有 SELECT 权限仍需要表、列、行范围与查询资源限制。

**FR-22 语义配置（V1.0）**

- 数据集定义字段、单位、粒度、别名、可用维度、指标、枚举、关联路径、时间字段与业务口径。
- 同系统多表通过已审核逻辑视图/关联定义支持；每个数据集有版本，schema 漂移进入不可用或待校验状态。
- 模型可以建议术语和关系，生效前由配置人员确认；不能把置信分数当作正确性证明。

**FR-23 问题转查询计划（V1.0）**

- 输出有类型的 QueryPlan：datasetId、datasetVersion、metrics、dimensions、filters、timeRange、orderBy、limit，具体字段以Schema为准；chartHint作为展示建议放入结果规划，不进入查询执行契约。
- 时间根据可信当前时间、时区及企业日历解析，使用半开区间；业务口径有歧义时追问。
- 问题超出当前已注册能力时明确说明，不能改用全库查询兜底。

**FR-24 受控查询与结果验证（V1.0）**

- 编译器把 QueryPlan 转为参数化 SQL 或 API 参数，字段/表来自服务端目录，授权范围由程序附加。
- V1.0 执行模型直接返回的任意 SQL 不在范围内；可展示实际编译 SQL 给有权调试的管理员。
- 防重复聚合、单位混算、null 误当 0、分页漏算；结果带 schemaVersion、timeRange、asOf、completeness。
- 错误修复次数有上限，重试不得改变权限与业务口径。

### 5.8 工具与执行流程

**FR-25 工具策略（V1.0 读工具，V1.1 写工具）**

- 工具定义用途、输入/输出 schema、权限、读写属性、超时、幂等策略、执行政策。
- 默认禁止新增工具执行；发布时明确 AUTO / CONFIRM / DENY。模型选择工具不构成授权。
- 人工确认绑定工具版本、具体参数摘要、主体与有效期；确认后变更参数必须重新确认。
- 写调用超时存在“结果未知”，不能自动标记失败并无限重试；必须支持业务幂等或核对。

**FR-26 有界执行（V1.0）**

- 支持“检索 → 查询 → 计算 → 展示”等可审计步骤，限制步数、耗时、工具次数和 token 预算。
- 每步记录输入输出引用和脱敏状态；不持久化模型隐藏推理。异步工作必须重建可信身份，不能继承线程里的旧用户。
- 图形化工作流设计器属于后续 FR-39。

### 5.9 智能报表

**FR-27 报表网页生成（V1.0）**

- 模型生成 ReportSpec，包含标题、说明、指标卡、表格、柱图、折线图和饼图布局；平台渲染为 Web 页面。
- 数据绑定到已执行结果或可审核查询定义，数值由计算提供，模型负责选择展示和解释。
- 所有图表适配自有 ChartSpec；任意 HTML/JS 不在首期执行范围。该约束满足现有框架禁直接 HTML 注入的规则。

**FR-28 保存、修改与版本（V1.0）**

- 支持“改成折线图”“增加地区对比”等对话修改；修改前校验现有查询能否提供所需字段。
- 保存快照或可刷新定义；报表所有者、应用、服务版本、查询版本、主题版本和引用资源明确记录。
- 报表修改生成新版本；并发修改使用版本冲突提示；首期私人报表，分享发布单独迭代。

**FR-29 刷新与读取（V1.0）**

- 快照展示数据截至时间；可刷新报表按当前用户权限重新执行原配置，成功后原子切换结果。
- 刷新失败保留旧结果并明确旧数据状态，不能伪装成最新。
- 浏览器点击图表钻取仅触发已定义的查询参数变化，并再次鉴权；首期只交付已明确实现的筛选交互。

### 5.10 运行、质量、交付

**FR-30 运行观测（V1.0）**

- 按应用/服务/模型聚合请求量、耗时、失败类型、token、工具调用和任务状态。
- 不以问题正文、用户名、密钥作指标标签。用 requestId/runId 关联排查；有权限才能查看受控会话正文。

**FR-31 配额与资源控制（V1.0）**

- 应用/主体维度并发、请求频率、token/任务预算；原子占用、结束或超时释放；失败不能永久占位。
- 上游未返回 token 数时标记未知或估算，不能填写 0 冒充实测。费用为配置单价估算，首期不做财务结算。

**FR-32 评测（V1.0）**

- 固定问题、输入数据、预期工具/计划/结果/引用/拒绝行为；固定模型、提示词与资源版本。
- 确定性计算结果比对与模型表现分开；评测报告显示失败样例，禁止只给一个综合分数。
- 发布、模型切换、提示词变化及上游升级必须运行受影响的回归集。

**FR-33 文件与附件（V1.0）**

- 上传校验大小、类型、魔数、路径、压缩展开量；默认私有；关联应用/主体/业务对象。
- 会话附件、知识原文、报表结果共用基础文件契约，但访问规则由各自业务拥有方判定。
- 长任务中的临时文件有清理和失败补偿，不能持久化临时凭证。

**FR-34 交付与升级（V1.0）**

- 自托管前端资源、SDK 和字体；核心流程不依赖公共 CDN。已配置外部模型的网络访问单独声明。
- 发布包附版本清单、SBOM、许可证、配置说明、迁移说明、验收证据和恢复方案。
- API/SDK/存量报表至少验证 N 与 N-1；数据库遵循 expand/migrate/contract。首次发布没有真实N-1时冻结首发候选产物作为未来兼容夹具，明确报告“首发基线验证”，不声称已验证历史发布版本。

### 5.11 后续能力

**FR-35 图像（V1.1）**：理解、OCR、生成、编辑分开探测；图片尺寸/格式/张数/存储/异步结果各有约束；生成结果仍是私有文件。失败不自动外发到另一提供商。

**FR-36 非实时语音（V1.1）**：STT/TTS、录音/播放、字幕与音频引用；配置格式、时长、语言和音色；浏览器授权被拒时可继续文本使用。

**FR-37 实时语音（V1.2）**：会话协商、短期凭证、打断、重连、静音和结束；模型网络通道仍受中台授权与审计；是否直连媒体网关需独立 ADR。

**FR-38 跨系统（V2）**：实体映射、口径/粒度、跨源执行、分源权限与时间一致性；先支持独立数据块汇总，再验证关联计算。现有 app_id 不能被当作跨企业 tenant_id。

**FR-39 扩展生态（V1.2）**：MCP 客户端、图形化流程、组件级嵌入；每项都通过适配器接入，按协议能力登记和独立回归，不默认安装整套 Agent 平台。

**FR-40 全链路安全（所有版本）**：提示注入、SQL/模板/路径注入、SSRF、越权、撤销、秘密保护、结果外发策略；拒绝路径属于正常产品能力，有稳定错误和审计。

## 6. 非功能验收目标

以下为建议验收基线，需在 P0 记录机器配置并确认；不是对所有模型和业务数据量的无条件 SLA。

| 编号 | 目标 |
|---|---|
| NFR-01 正确性 | 已支持的确定性 SQL/API 统计用例预期结果 100% 一致；浮点与金额按契约比较 |
| NFR-02 理解质量 | 冻结模型和问题集后，明确可回答问题意图/计划命中率 >=95%；含糊问题追问和越权拒绝单独统计，不混入成功率 |
| NFR-03 安全 | 安全用例中越权、密钥泄漏、任意执行成功数为 0；任一出现阻断发布 |
| NFR-04 基础性能 | 建议 8 vCPU/16GB 测试环境，20 个并发 run；Mock 模型固定响应时平台受理 P95 <=500ms，状态查询 P95 <=300ms；模型与数据源耗时单独记录 |
| NFR-05 可靠性 | 重启恢复、重复请求、取消、故障补偿全部有实测；不承诺外部写操作 exactly-once |
| NFR-06 前端 | 360/768/1440 宽度、深浅主题、跨源嵌入、键盘操作无关键阻断；SDK 基础包目标 gzip <=100KB，图表按需加载并记录预算 |
| NFR-07 运维 | 延续框架 RTO 4h/RPO 1h 目标，覆盖 MySQL、文件、索引和必要密钥的可恢复性；实际恢复演练取证 |
| NFR-08 工程 | 既有 Harness 全通过；新文件覆盖率 >=80%；新增包和门禁均接入真实检查 |

## 7. 首期验收用户故事

1. 管理员注册应用，配置模型并完成真实能力探测。
2. 研发接入一个读取统计数据的 API 和一个 MySQL 只读数据集，业务人员配置指标含义。
3. 上传知识文档，成功索引，限定应用与用户范围。
4. 配置并发布服务，第三方从标准文档完成服务调用。
5. 第三方嵌入 Chat，主题与宿主协调，身份及上下文正确传递。
6. 用户问业务问题获得准确查询结果及图表；问知识问题获得可点击且有权读取的引用。
7. 用户修改并保存报表，后续刷新获得新数据；失权后读取与刷新被拒绝。
8. 上游超时、任务重启、授权撤销和 SDK 断线都有明确行为。
9. 完成一次依赖升级和恢复演练，旧版本 SDK 与存量报表仍可使用。

## 8. 首期明确排除

模型训练与 GPU 调度、多企业共享 SaaS、多系统即时关联、任意代码执行、任意自然语言直写业务库、公共匿名分享、完整 BI 拖拽设计器、全供应商多模态适配。需求保留与范围扩展必须有任务和验收，不以隐藏开关提前塞进产品。
