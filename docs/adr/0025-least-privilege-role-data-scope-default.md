# ADR 0025：新角色默认仅本人数据范围

## 状态

已接受

## 背景

角色创建请求不包含数据范围字段，但 `RoleServiceImpl#createRole` 和数据库列默认值都将
新角色初始化为 `ALL`。这意味着调用方漏传字段、内部调用传入错误值或绕过 ORM 的
受控写入都会以最大数据权限开始。项目即使只对部分应用表启用数据权限，该默认值仍会
让新角色在启用规则的表上形成不必要的横向访问。

## 决策

- 所有新角色由 Service 强制初始化为 `SELF`，不接受创建对象夹带的数据范围。
- Flyway 将 `system_role.data_scope` 的列默认值改为 `5`，与 Java 枚举和 Service
  语义一致；最终 SQL 快照同步更新。
- 扩大数据范围只能调用独立的角色数据范围分配命令，该入口继续要求专用权限、
  目标校验、操作审计和会话撤销。
- 迁移只修改列默认值，不回写存量角色，避免改变管理员已明确配置的业务权限。

## 影响

新角色在完成菜单和数据范围授权前保持最小能力。未装配数据权限规则的表不会因为角色
范围值变化而被额外过滤；需要全量数据访问的项目仍可通过显式授权获得 `ALL`。Service
单元测试防止默认值回退，真实 MySQL 集成测试校验迁移后的列默认值。
