# ADR 0015：文件删除采用持久化待清理状态

## 状态

已接受，2026-08-29。

## 背景

数据库事务无法覆盖本地磁盘、数据库文件客户端和 S3 对象删除。原流程先删除外部对象，再删除
`infra_file` 元数据；批量操作中途失败时，数据库回滚会恢复已经失去外部对象的引用。

## 决策

1. 删除请求先在数据库事务内锁定目标记录，并把 `infra_file.delete_status` 从正常切换为待清理。
2. 列表和单条查询只返回正常记录，因此事务提交后业务侧立即视为已删除。
3. 事务提交后逐个幂等删除外部对象；成功后物理删除元数据，失败则记录异常类型、失败次数和下一次重试时间。
4. `fileDeletionRetryJob` 每分钟扫描有限批次的到期记录，按指数退避继续补偿。退避批量与时间上限由
   `basic-framework.infra.file-deletion` 配置拥有。
5. 失败记录不保存异常消息和路径，避免把供应商响应、签名参数或业务文件名写入数据库与日志。

## 结果

- 外部对象已删除但元数据仍可见的悬挂引用窗口被消除。
- 外部存储短暂故障不会丢失清理意图；对象删除成功但元数据删除失败时，也可依赖幂等重试收敛。
- 待清理行仍引用文件配置，配置删除会继续被既有外键和引用计数阻止。
