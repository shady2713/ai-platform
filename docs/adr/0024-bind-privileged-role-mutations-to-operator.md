# ADR 0024：超级管理员角色变更绑定真实操作者

## 状态

已接受

## 背景

角色菜单、角色数据范围和用户角色分配入口已有专用权限，但服务方法
原先只接收目标角色或用户。持有普通分配权限的管理员可直接调用服务触及
`super_admin`，后台任务也无法表达“谁正在授权”。由于超级管理员绕过普通权限与
数据范围，Controller 鉴权不能构成完整的权限提升边界。

## 决策

- 三类授权命令都显式接收 `operatorUserId`，HTTP 入口只传当前认证用户编号。
- 一次用户角色变更同时检查变更前和变更后的角色集合；因此授予、撤销或在保留
  `super_admin` 时调整其他角色都属于触及特权角色。
- 目标为 `super_admin` 的菜单或数据范围变更同样检查操作者。操作者必须持有启用中
  的 `super_admin`，否则以稳定业务错误码失败，且不读取或写入授权关系。
- 会话撤销语义保持不变：合法的角色或权限变化继续撤销受影响的管理端会话。

## 影响

内部调用方也必须提供真实操作者，不能再把目标主体或固定系统账号当作无语义参数。
普通角色授权能力维持现状；本决策只保护具有全局绕过能力的超级管理员角色。若未来
需要服务账号代授权，应引入可审计的主体类型和显式策略，而不是绕过该检查。
