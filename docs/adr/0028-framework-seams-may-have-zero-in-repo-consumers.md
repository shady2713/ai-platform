# ADR 0028：框架能力缝允许零仓库内消费者

- 状态：已接受

## 背景

`basic-framework-spring-boot-starter-protection` 交付三个请求保护能力：
`@RateLimiter`（限流）、`@Idempotent`（幂等）和可选的 Lock4j 分布式锁。审计发现
`@RateLimiter` 在 system/infra 模块有 4 个真实消费点（登录、验证码、短信等），而
`@Idempotent` 在仓库业务代码中没有任何消费点——注解、切面、3 个 KeyResolver、
Redis DAO 及其测试全部就位但无人调用。按"无死代码"规则，这类零消费者通常应删除。

## 决策

1. `@Idempotent` 是框架对外交付的**能力契约**，不是仓库内部工具：它面向使用该框架的
   下游项目，由下游按端点自行选择启用。契约的证明是 README 的使用约束 +
   `IdempotentAspectTest` 等单元测试，而非仓库内业务调用点。
2. 保持该缝不删除，但不再允许其"静默存在"：README 必须说明启用条件与默认行为，
   切面测试必须持续钉住契约（key 非空、超时大于 0、Redis 不确定结果按失败处理）。
3. 仓库内任何集成端点若出现需要幂等保护的场景，应先于新增手写重复防护逻辑使用该缝；
   若长期无消费者且无下游引用，按常规死代码规则复核删除。
4. 本决策不影响"能力缝必须被真实使用才声称受支持"的边界：未被消费的能力不得在
   能力目录中宣称"已被生产验证"，只能声明"已交付并通过契约测试"。

## 后果

- 框架交付目录保留幂等能力，下游无需自行实现。
- 死代码检出规则对该缝适用"有契约测试的对外能力"例外，仓库级质量门禁（源码扫描、
  覆盖率棘轮）继续以测试形式覆盖它。
- 后续若删除该缝，需同步本 ADR 状态与能力目录条目。
