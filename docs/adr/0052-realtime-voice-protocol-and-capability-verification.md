# 0052：实时语音的协议选择与端点能力验证

日期：2026-09-27。状态：采用（X05 交付规划，真实供应商链路未验证）。

## 背景

FR-37 要求实时语音会话：会话协商、短期凭证、打断、重连、静音和结束；模型网络通道仍受中台
授权与审计，是否直连媒体网关需独立 ADR。X01 已在 `ModelCapability` 冻结"非实时"媒体能力
（STT/TTS），并明确**不预留**实时占位值；实时语音需要会话协商与短期凭证的独立契约。

实时语音与既有非实时媒体（X03/X04 的任务受理-执行分离）有两点根本不同：

1. 会话是**有寿命的在线资源**：它占用上游并发通道和平台网络资源，超时、断线、切用户都必须
   关闭；不能像媒体任务那样"排队等后台租约"。
2. 供应商协议不统一：同一份"实时语音"在不同的目标端点上可能是 WebSocket 上的 JSON 事件 +
   分帧音频，也可能是 WebRTC 媒体通道 + 信令面。**没有任何一项能力可以按"供应商"或
   "模型名"推断出来。**

因此必须先决定：平台怎么确认"这个端点的这个协议真的可用"，以及 WebSocket 与 WebRTC 之间
怎么选。本 ADR 只冻结判据与边界，不假设任何供应商行为。

## 决策

### 1. 能力验证：声明 + 真实探测确认，缺一不可；验证结果按（端点, 配置版本, 协议）缓存

平台对实时语音只发布**已验证事实**：

- **声明（declared）**：目标端点所属的实时适配器声明它在该协议下支持哪些
  `RealtimeCapability`（`SESSION_NEGOTIATION`、`AUDIO_INPUT_STREAM`、`AUDIO_OUTPUT_STREAM`、
  `SERVER_VAD_INTERRUPTION`、`INCREMENTAL_TRANSCRIPTION`、`TOOL_CALL_BRIDGE`）。
- **确认（confirmed）**：平台用适配器提供的 `RealtimeCapabilityProbe` 发起一次**真实**能力探测
  （最小会话协商 + 最小音频往返，使用平台内置合成夹具，不使用真实用户数据），得出
  `RealtimeCapabilityReport`。
- **可发布范围 = 声明 ∩ 确认 ∩ 该协议的必需能力**（`RealtimeProtocolVerification`）。任一必需能力
  不在交集中 → 拒绝受理会话，稳定原因码说明缺哪一项，**不回退**到其它协议、端点或供应商。
- 验证结论按 `(endpoint_id, config_revision, protocol)` 落 `ai_realtime_endpoint_capability`
  （只存结论与稳定明细码，不存凭据与上游报文）。端点配置版本变化后旧结论不再覆盖当前配置，
  必须重探（与非实时媒体探测同一口径）。探测是**惰性**的：受理时按需执行一次，失败结论在冷却
  窗口内不重复外发（避免把会话受理变成探测风暴）。

没有注册适配器的协议 → 探测结论是 `ADAPTER_NOT_IMPLEMENTED`，受理直接拒绝。这是平台"不假设
供应商一致"的落点：**平台不知道的能力一律不可用**，不允许用"别的供应商能用"来推断。

### 2. WebSocket 与 WebRTC 的选择判据

选择只由**已验证事实**驱动，不由偏好驱动：

| 判据 | WebSocket | WebRTC |
|---|---|---|
| 媒体通道 | 分帧音频走应用层消息（平台/适配器负责分帧与序号） | 媒体走 SRTP 通道（浏览器↔上游），平台只做会话协商与事件面 |
| 打断实现 | 平台回合栅栏 + 上游取消事件 | 依赖上游服务端 VAD/打断，平台仍保留回合栅栏 |
| 必需能力 | `SESSION_NEGOTIATION`、`AUDIO_INPUT_STREAM`、`AUDIO_OUTPUT_STREAM` | 加 `SERVER_VAD_INTERRUPTION`（媒体面在浏览器与上游之间，平台无法逐帧拦截） |
| NAT/ICE | 不需要 | 需要，部署与排障复杂度高 |
| 浏览器支持面 | 广（既有端口与代理即可） | 需要 ICE/DTLS/SRTP 与安全上下文，设备矩阵必须实测 |
| 适用场景 | 上游只提供事件+分帧音频；企业内网/代理环境 | 上游提供媒体面能力，且要求浏览器↔上游直连媒体 |

规则：

1. 客户端**显式请求**协议（`RealtimeProtocol`），平台不做隐式降级或升格；
2. 请求的协议在该（端点, 配置版本）上**未通过验证** → 409 稳定错误码
   （`AI_REALTIME_PROTOCOL_UNVERIFIED`），客户端可改用另一协议重试；
3. 平台不"自动挑选供应商"：协议与端点都由请求显式给出，失败不转移到其它端点；
4. 同一会话的协议在受理时固定，重连（resume）只能沿用；换协议=新建会话。

### 3. 会话边界（与协议无关的平台语义）

- **受理即固定**：端点编号、配置版本、凭据版本、协议、音频格式、会话绝对到期时间在受理时
  写入会话行；短期票据只存摘要、明文仅在受理响应出现一次。
- **背压有界**：输入音频按字节计账，超过会话缓冲上限即按稳定原因结束会话（
  `AUDIO_BACKPRESSURE_EXCEEDED`），**不允许静默丢帧**。
- **打断即栅栏**：打断推进回合号；晚到的旧回合音频/转写事件按"过期帧"丢弃并计数，
  绝不继续输出（AT-069 的核心断言）。
- **重连有界且幂等**：重连有次数与时限上限，超出即关闭（`REATTACH_BUDGET_EXCEEDED` /
  `REATTACH_TIMEOUT`）；工具执行按（会话, 回合, 调用）唯一键去重，重连不重复执行工具。
- **到期/切用户关闭**：到期与"会话被另一个主体访问"都会关闭会话（`SESSION_EXPIRED` /
  `IDENTITY_SWITCHED`）——身份不可跨会话复用。关闭是惰性的（在读取/使用时判定），
  不新增常驻扫描任务（X10 教训）。
- **并发受限**：同一主体与同一应用的并发会话数有上限，超限拒绝（429/稳定码），
  不排队、不阻塞。

## 未验证项（明确登记，不得当作已验证）

本环境**没有**任何真实供应商的实时语音凭据与出网通道，因此：

- 真实供应商的实时链路（真实 WebSocket/WebRTC 媒体面、真实服务端 VAD、真实转写/工具事件）
  **未验证**；本卡只验证平台侧垂直流程与"本地协议替身"。
- 设备/浏览器矩阵（Chrome/Safari/Firefox/移动端与 WebRTC 的 ICE/编解码/自动播放策略）
  **未验证**：允许路径内没有真实浏览器套件与真实网关可跑，`tests/**` 不在本卡允许路径内。
- WebRTC 媒体面（ICE/DTLS/SRTP、媒体权限、编解码协商）在平台侧只有契约与判据，
  **未做真实连通性验证**。
- 上述"未验证"结论不因为"平台侧替身跑通"而改变；真实供应商接入必须补真实端到端证据。

## 后果

- 会话受理的成功路径**必须**有真实探测确认；平台任何"按供应商/模型名推断协议"的实现都与本
  ADR 冲突（由 `AiRealtimeEndpointVerifier` 的判定顺序保证：先验证，再打开通道）。
- 因无真实适配器，本仓库默认状态下实时会话受理按 `AI_REALTIME_ADAPTER_UNAVAILABLE` 拒绝；
  测试用本地协议替身（server 测试域注册的适配器）证明平台流程，生产接入需补真实适配器与
  真实探测证据。
- 打断与背压是**平台层不变量**，即使上游声称支持服务端 VAD 也保留回合栅栏（不信任上游时序）。
