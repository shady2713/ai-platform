# ADR 0018：文件读取策略与所有权边界

- 状态：已接受

## 背景

文件下载路由需要兼容本地、数据库存储和应用端接入，因此保留了匿名可达的路径。仅校验存储配置编号和路径会让任何能猜到路径的请求绕过文件业务归属，也无法区分需要公开展示的图片和私有材料。

## 决策

1. `infra_file` 持久化 `access_type`（公开/私有）和上传主体的所有者编号、类型。新文件默认私有；公开读取必须由上传请求显式传入 `publicRead=true`。
2. 下载前必须先以 `config_id + path + 已完成 + 未删除` 查找元数据，再决定是否读取存储对象；不得直接把请求路径交给 `FileClient`。
3. 公开文件可匿名读取。私有文件仅允许所有者或拥有 `infra:file:query` 的管理员读取；拒绝和不存在均返回 `FILE_NOT_EXISTS`，避免文件枚举。
4. 私有文件只能写入具备受控读取能力的存储。公开 S3 Bucket 不得接收私有文件；本地和数据库存储的读取必须经过应用下载接口。
5. V37 将已有记录显式标为公开，并从历史预签名上传主体回填可得的所有者信息，以保持升级前的可访问性。历史缺失主体的记录不能被转换为私有。

## 后果

- 应用端、小程序、APP 和 H5 仍可通过公开文件 URL 对接；需要私有读取时必须携带认证凭据或由业务端申请受控的存储读地址。
- 新接入方不再因默认公开而泄露附件；公开展示的头像、商品图等调用方必须作出明确选择。
- 对象存储若需要同一 Bucket 同时承载公开和私有对象，应使用可按对象实施访问策略的适配器；本框架的公开 Bucket 配置只承载公开对象。
