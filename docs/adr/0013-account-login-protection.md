# ADR 0013：账号级登录失败保护

## 状态

已采纳。

## 背景

登录入口已有客户端 IP 限流，但分布式攻击可以更换来源地址持续尝试同一账号。仅按
用户名创建 Redis Key 又会允许匿名调用方制造无界键空间，因此保护状态只绑定已存在
用户的内部编号。

## 决策

- 账号密码登录在 15 分钟窗口内连续失败 5 次后锁定 15 分钟；阈值和时长由
  `basic-framework.security.login-protection` 的校验配置拥有。
- Redis 使用“失败计数”和“锁定状态”两个短时 Key，并通过 Lua 原子完成计数、过期与
  锁定切换。Redis 异常时认证失败，不静默绕过保护。
- 正确的账号密码、密码重置以及管理员解除锁定会清除失败状态。管理员命令使用
  `system:user:update` 权限 和操作审计。
- 锁定状态与普通账号密码失败返回相同文案和业务码，避免形成账号枚举信号；管理员从登录
  审计结果识别锁定。现有 IP 限流继续保留，二者互不替代。

## 影响

该方案不增加数据库状态，应用重启不会丢失锁定状态，但 Redis 数据清空会清除短时保护。
攻击者仍可能针对已知账号制造短时拒绝服务，因此锁定时间有限，并保留管理员解锁入口。
