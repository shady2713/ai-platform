# ADR 0021：成功认证后升级密码哈希

## 状态

已采纳。

## 背景

BCrypt 工作因子由部署配置拥有。提高配置只能影响新设密码；如果没有迁移机制，历史账号即使持续
登录，也会永久保留较低成本哈希。批量离线重编码不可行，因为服务端不保存用户明文密码。

认证成功后已经短暂持有经过验证的原始密码，可以机会式生成当前强度哈希。但按用户编号直接更新
会与用户改密或管理员重置竞争：后发生的机会式写入可能用旧密码覆盖已经生效的新凭据。

## 决策

- 仅在用户名密码匹配、账号启用后调用 `PasswordEncoder.upgradeEncoding`；当前强度哈希不触发数据库写入。
- 需要升级时使用当前 `PasswordEncoder` 重新编码已验证密码。
- 数据库更新同时匹配用户编号与认证时读取的旧哈希。更新零行表示账号已删除或凭据被并发修改，
  此时不得重试覆盖。
- 编码或数据库异常向登录链路传播，令本次登录失败；不能在迁移失败时静默签发新会话。
- 只改变盐值或工作因子的成功升级不撤销已有会话，也不记录密码或哈希内容。

## 影响

活跃账号会随成功密码登录逐步迁移到当前 BCrypt 强度，无需保存明文或执行离线破解。每个待升级
账号首次成功登录会额外承担一次 BCrypt 编码和一次条件更新；迁移完成后的登录只有常规验证成本。
compare-and-set 写入保证机会式迁移不能覆盖并发发生的真实密码变更。
