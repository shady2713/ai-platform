# ADR 0039：跨刷新代次撤销同一会话

状态：接受

## 问题

刷新已提交而响应尚未到达时，登出携带的旧访问令牌和旧刷新令牌已无法按当前摘要找到会话。迟到的 Set-Cookie 因而可能留下仍能恢复登录的凭据。

## 决策

刷新令牌由稳定的 256 bit 随机撤销凭据与每次轮换的 256 bit 随机秘密拼接组成。完整令牌摘要仍是一用即失效的刷新证明；稳定部分的摘要仅供登出定位同一会话，不参与刷新认证。

V44 增加可为空且唯一的撤销凭据摘要。旧 64 位十六进制令牌首次刷新时整体成为稳定部分，新令牌为 128 位十六进制字符串；升级前后均可通过旧 Cookie 登出。撤销用一次数据库查询匹配稳定摘要或旧完整摘要，避免首次升级发生在分开的兼容查询之间。

不增加新的 Cookie 或前端协议字段；旧代持有者只能撤销所属会话，不能重放刷新或影响其他会话。

刷新路径执行重用检测（RFC 6819）：完整摘要失配但稳定摘要命中存活会话时，视为旧代令牌被盗重放，吊销该会话并记录安全日志，随后仍返回刷新令牌无效。前端刷新单飞（refreshTokenQueue）只覆盖单标签页；两个标签页共享 Cookie 且并发刷新时，后到者持旧代令牌会触发吊销，双方均需重新登录。这是该检测的既定可用性代价：误吊销仅造成重新登录，而被盗令牌则即刻失去价值并留下告警痕迹。另一种并发形态是双方同时读到同一代会话行、条件更新只放行先到者：后到者的摘要本身命中（读取发生在轮换提交前），不属于上述重放场景，因此只返回刷新令牌无效而不吊销；其再次持旧令牌请求时会命中完整摘要失配分支，吊销在那一拍仍然生效。该分支若同步吊销，多标签页正常并发刷新将必然互杀，可用性代价不可接受。

## 验证

单元测试验证协议长度、摘要、随机令牌、非法值及旧代撤销定位，并覆盖旧代重放吊销存活会话、未知令牌不影响其他会话两条重用检测路径。`SessionConcurrencyIT` 在真实 MySQL 上验证多次刷新后的旧 Cookie 登出、旧版升级前后兼容、首次升级提交与登出的并发竞争，以及其他会话不受影响。
