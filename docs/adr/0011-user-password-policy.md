# ADR 0011：用户自选密码边界

- 状态：已接受

## 背景

旧规则只在前端要求 6-16 位 ASCII 大小写字母和数字，后端设密入口仅校验非空。
这既可被绕过，也会静默修改首尾空格。系统使用 BCrypt；其输入只处理前 72 字节，
因此把表单上限直接扩大到 128 个字符会制造不同明文得到同一有效输入前缀的风险。

## 决策

1. 用户自选密码至少 15 个 Unicode 码点，UTF-8 编码最多 72 字节；不要求固定字符组合。
2. 密码不 trim、不规范化、不截断，原样进入 BCrypt，并继续禁止回显和记录日志。
3. 创建用户、管理员重置、自助改密和短信重置的后端边界都执行结构校验；服务层再拒绝本地高频弱密码、低字符多样性、账号名和部署配置的品牌保留词。
4. 登录只校验非空并按原文匹配已有哈希，避免新策略阻断历史账号；策略只约束新设密码。
5. 双端结构规则和测试向量登记在 `docs/contracts/field-catalog.yaml`。离线基础框架不宣称覆盖在线泄露密码库；项目需要该能力时在服务策略外接明确失败语义的 Provider。

## 后果

- 所有 HTTP 和服务调用路径都有同一后端安全下限，前端仅负责即时反馈。
- 非 ASCII 密码受 72 字节上限影响会比 ASCII 更早达到上限，表单提示必须说明字节边界。
- 既有短密码仍可登录，但下一次设密必须满足新策略。
