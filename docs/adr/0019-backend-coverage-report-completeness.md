# ADR 0019：后端覆盖率报告完整性

- 状态：已接受

## 背景

单文件覆盖率棘轮原先只遍历已有的 JaCoCo XML。没有测试的 Maven 模块不会生成报告，
其生产源码因此既没有覆盖率下限，也不会被识别为未登记文件；这使整模块可以绕开门禁。

## 决策

1. 覆盖率脚本枚举每个含 `src/main/java` 的 Maven 模块；模块未生成 JaCoCo 报告时，
   除 `package-info.java` 外的每个生产源码按 0% 加入当前覆盖率。
2. 不设置源码豁免清单。包括独立 `*-api` 薄契约模块在内，所有生产模块都必须运行测试并
   生成 JaCoCo 报告。
3. 默认方法、显式构造器等可执行契约逻辑按实测值进入正常 `backend` 基线；纯抽象声明和
   被 JaCoCo 过滤的生成代码没有可覆盖行，不伪造无业务价值的覆盖率。

## 后果

- 无报告模块不再是门禁盲区，且不存在可以长期隐藏普通源码的零覆盖率豁免。
- 契约模块的可执行行为与普通代码遵循同一套覆盖率棘轮，覆盖率只能从当前实测值向上演进。
