# ADR 0023：数据权限豁免必须附带可验证控制证据

## 状态

已接受

## 背景

应用表原先必须登记部门/用户运行时规则或进入豁免台账，但豁免只包含分组、表名和文字理由。
理由即使与实现脱节，contracts gate 仍会通过；授权关系表也确实存在入口已鉴权、Service 却未先
校验目标用户、角色和菜单状态的缺口。因此“已分类”不能等同于“替代控制仍然存在”。

## 决策

- 豁免契约升级为版本 2；每个分组必须提供 `controls`，并完整覆盖组内每张表。
- 控制类型限定为功能权限、主体绑定、凭据绑定、所有者或管理权限、目标校验、内部写入六类。
- 每项控制必须引用仓库内生产 Java 源码及已审查的关键片段。文件删除、片段漂移、测试源码取证、
  目录穿越、组外表引用或未覆盖表都会阻断 contracts gate。
- `system_role_menu` 写入前校验角色和菜单，`system_user_role` 写入前校验用户和角色；不存在或
  已禁用的目标在读取、修改关联表前失败。

## 影响

数据权限豁免从一次性文字声明变成随实现同步演进的安全契约。源码重构若改变控制位置，必须同时
更新证据并重新审查控制语义。片段存在只能证明已登记的控制没有静默消失，不能替代业务授权测试；
因此敏感主体过滤、凭据原子消费和授权目标校验仍由各模块单元测试覆盖。
