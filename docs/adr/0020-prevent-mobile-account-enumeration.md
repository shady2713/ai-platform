# ADR 0020：防止匿名认证账号枚举

## 状态

已采纳。

## 背景

短信发送与忘记密码接口允许匿名访问。旧实现会在手机号未注册时分别返回“手机号不存在”
或“该手机号尚未注册”，攻击者即使无法取得短信验证码，也能通过业务响应批量确认后台账号。
客户端 IP 限流能降低单一来源的速度，但不能阻止分布式枚举。

账号密码登录虽然对不存在、锁定和密码错误统一返回“账号密码不正确”，但旧流程在不存在或
锁定分支跳过 BCrypt。攻击者可通过重复采样密码学成本差异，建立用户名或锁定状态的时序旁路。

## 决策

- 短信发送仍先执行图形验证码等场景校验；手机号未知时不创建验证码、不发送短信，但返回与
  已存在账号相同的受理成功结果。
- 密码重置先原子消费一次性短信码，再查询账号。验证码有效但账号已删除时返回通用成功，
  不更新密码，也不清除其他账号的登录保护状态。
- 图形验证码错误、短信码错误、频率限制和存储故障继续显式失败；只有“账号是否存在”这一
  信息被隐藏。
- 用户名不存在或账号已锁定时，使用部署实际的 `PasswordEncoder` 对启动期生成的假哈希执行
  一次 `matches`；假哈希跨请求复用，使请求期成本与正常 BCrypt 校验同阶，且不生成请求级哈希。
- 客户端统一提示“若账号存在，后续操作将生效”，不得把成功响应解释为短信已发送或密码已修改。

## 影响

匿名调用方无法再通过业务码、错误文案或是否执行密码哈希的明显成本差异确认账号状态。合法账号
的发送和重置流程不变；输入未知手机号时，接口由业务错误改为通用成功，因此依赖旧错误码的
外部客户端需要移除该判断。服务启动会额外生成一次当前 BCrypt 强度的假哈希，未知与锁定账号的
登录请求会承担一次正常密码校验成本。
