# 0050：报表受控分享的可见权与源数据读取权分离

日期：2026-09-27。状态：采用（X11 交付）。

## 背景

报表是私人产物（FR-28）：归属按"应用 + 主体类型 + 外部用户标识"三元组判定，读取逐项复核
保存时的 A03 范围指纹。业务需要把报表分享给同应用内的其他用户（FR-05/29/40），但存在两条
不可接受的捷径：把授予者的数据权限一并交给接收者（越权放大），或把版本内容物化进分享行
（授权回收后数据仍可读）。需要先冻结分享的权限语义，再交付实现。

## 决策

1. **两种权利分离**。分享凭据（`ai_report_share`）只授予"可见权"——谁能打开这份分享、
   看到签发时固定的哪个版本；内容出库前按**接收者自己**的当前 A03 授权逐项复核
   （`reauthorizeHistorical` 放行且复现保存时的范围指纹才算覆盖）。覆盖不了进入**降级态**：
   HTTP 200 但 `specJson`/`dataJson`/`asOf`/`completeness` 全空（隐藏统计与快照不出库），
   `reasonCode=scope-uncovered`。可见性是授予者有意签发的，所以不抛 404；
   内容覆盖不了，所以不给内容。
2. **凭据只存摘要**。明文令牌为 32 字节 `SecureRandom` → Base64URL，仅在创建响应出现一次；
   存储与校验只用其 SHA-256 摘要（唯一键）。库泄露不等于凭据泄露，日志与审计永不回显明文。
3. **失效即读不到，且对外不可区分**。撤销（授予者 CAS）、到期（读取时惰性物化，不设常驻
   扫描任务）、授予者主体停用、凭据未知、非接收者——五类前置失败对外统一 404
   （`AI_REPORT_SHARE_NOT_EXISTS`，后缀承重，ADR 0003），稳定原因只进访问审计
   （`ai_report_share_access`，append-retention，仅授予者可查）。
4. **公开匿名链接与固定快照分享（脱离源 ACL）不在本卡**：两者分别绕过"仅已登录且获授权
   主体之间分享"与"读取仍按接收者当前源权限"的边界，需要另立审批设计（详见
   `docs/contracts/ai/report-share-permissions.md` 第 5 节）。

## 后果

- 分享给无源权限的用户只能"看见分享存在"，拿不到隐藏统计与快照（验收条目由此可测）；
- 撤销立即影响新读取，历史版本同样拒绝；授予者离职后入口默认关闭（保留规则可验证）；
- 到期不依赖 Quartz 任务（X10 的教训：常驻无界扫描伤请求延迟），由读取路径惰性物化；
- 复制 reportId / shareId / 版本号不构成读取入口：读取只认令牌摘要与接收者主体绑定。
