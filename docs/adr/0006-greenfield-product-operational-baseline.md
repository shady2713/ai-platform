# ADR 0006：产品与运行基线

- 状态：已接受

## 上下文

本仓库用于打造全新的管理后台基础框架。产品边界必须明确，避免留下看似可用、
实际缺少安全与运维闭环的半成品能力。

## 决策

| 领域 | 决定 | 约束 |
|---|---|---|
| 用户名 | 小写 ASCII，且以字母开头 | 写入前 canonicalize；唯一键和登录查询使用相同语义 |
| 多租户 | 单租户 | 不保留租户参数、表字段或配置假象；启用前必须重新设计隔离模型 |
| 富文本 | 不提供 | 只接收纯文本；引入前必须定义 sanitizer、CSP、大小限制和版本策略 |
| 外部开放 API | 不提供 | 不保留签名、公共客户端或兼容周期等未闭环入口 |
| 敏感身份/金融数据 | 基础框架不收集身份证、银行卡等数据 | 新业务引入前必须定义目的、权限、保留期和删除/匿名化规则 |
| 数据库关系 | 混合策略 | 稳定强一致关系用物理 FK；其余关系必须有索引、写入校验和孤儿审计 |
| 删除 | 按聚合决定 | 软删、硬删、追加保留和平台托管必须逐表登记，不能由通用基类隐式决定 |
| 传输上限 | 默认收紧 | JSON/Form body 1 MiB、URI 8 KiB、请求头总计 32 KiB；上传逐端点声明 |
| 发布兼容 | 发布后支持 N/N-1 | API 和 Schema 遵循 expand/migrate/contract |
| 恢复目标 | RTO 4 小时、RPO 1 小时 | 通过备份恢复演练验收；业务等级提高时再收紧 |
| 会话撤销 | 分级立即撤销 | 改密、禁用、删除、角色或权限变化撤销受影响的 access/refresh 会话并审计 |
| MQ | 当前不提供 | MQ starter 已随精简移除（ADR 0030）；未来引入时必须满足有限重试后进 DLQ、幂等回放和处置审计的边界 |
| 工程生命周期 | Maven Wrapper、pnpm 和 CI 是唯一入口 | 不维护第二套编排状态 |

手机号采用中国大陆 11 位号码语义；用户名在写入和查询前统一 trim、NFC 规范化并转小写。
HTTP 状态语义以 ADR 0003 为准。

## 发布边界

- 首次共享环境发布前如需重建 Flyway 基线，必须单独记录决策并同步空库、快照和篡改验证。
- 任一 migration 在共享环境执行后立即冻结，只能通过更高版本 migration 演进。
- 任何偏离本 ADR 的需求必须先形成新 ADR，不得通过局部特判改变平台边界。
