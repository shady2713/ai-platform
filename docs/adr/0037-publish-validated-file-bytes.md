# 0037 — 发布已经校验的文件字节

状态：已采纳

## 背景

预签名 PUT 在有效期内可以重复使用。完成接口读取临时对象并检查大小、MIME、扩展名和压缩包之后，如果再按对象键执行服务端复制，上传者可以在检查与复制之间替换同长度内容；最终大小检查无法识别这种替换。

## 决策

完成接口把已经检查过的内存字节通过现有 `FileClient.upload` 写入最终路径，确认存储大小后删除临时对象，再将元数据标记为完成。客户端仅持有临时路径的 PUT 权限。删除没有其他调用方的 `promotePrivateUpload` 扩展与 S3 CopyObject 实现。

签发通过事务覆盖配置共享锁与待上传记录的写入。完成入口挂起调用方事务，先独立提交 `VALIDATING` 认领状态，再在发布事务内按“配置共享锁、文件更新锁”的顺序复核状态、验证内容并发布。发布失败先回滚该事务，再登记持久化删除补偿。过期清理与发布争用同一文件行：先清理的记录不能重新发布，先发布成功的记录不再满足过期清理条件。

## 代价与验证

发布增加一次从应用到对象存储的数据传输，换取验证内容和最终内容一致的明确边界。现有上传大小限制继续约束内存与带宽消耗，失败对象继续进入持久化删除补偿。

回归测试在读取临时对象后立即用同长度非法字节替换存储对象，断言最终文件仍逐字节等于通过校验的原始内容，临时对象被清理。

真实 MySQL 集成测试保留完整 Spring 服务与事务代理，仅替换外部存储，验证无调用方事务时的签发与完成、发布失败后的持久化补偿，以及发布与过期清理两种先后顺序。
