# ADR 0012：文件上传元数据边界与失败补偿

- 状态：已接受

## 背景

管理端和应用端都支持后端直传及预签名上传。原请求对象未完整约束 `infra_file`
列宽，服务也可能在对象存储上传成功、数据库写入失败后留下孤儿文件。

## 决策

1. `FileMetadataLimits` 是文件名、目录、路径、URL、MIME 和大小边界的唯一代码来源，数值不得超过 `infra_file` 最终列定义。
2. 管理端与应用端使用各自的请求契约，但共同引用这些边界；服务层再次校验，防止内部调用绕过 Controller。
3. 预签名上传只对私有 S3 存储开放。服务端在签名时写入不可见的待完成记录，仅持久化随机凭据摘要、登录主体、预期大小与过期时间；不接受客户端回传路径、配置或访问地址。
4. 后端直传完成后，若元数据校验或数据库写入失败，立即调用同一 `FileClient` 删除已上传对象；补偿失败作为 suppressed exception 保留给服务端日志。
5. 路径继续执行相对路径、控制字符和目录穿越检查；具体存储客户端仍必须做自己的规范路径校验。
6. 完成接口按凭据摘要、登录主体和未过期状态原子认领记录，从存储端重新读取对象内容与元数据，验证大小、MIME、扩展名和压缩包安全后才发布。同一主体重试返回已验证地址；过期或校验失败的对象进入持久化删除补偿流程。

## 后果

- 非法或超列宽元数据在外部写入前尽早失败，管理端和应用端行为一致。
- 数据库故障不再静默积累已知孤儿对象；进程崩溃等不可捕获窗口仍需对象存储生命周期策略兜底。
- 预签名上传的访问地址只在服务端完成实际对象校验后返回；客户端重试不会重复发布。
- 未完成、过期或校验失败的对象与元数据由持久化清理任务收敛，对象存储生命周期策略作为最后一道保险。
