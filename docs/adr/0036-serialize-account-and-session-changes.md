# ADR 0036：账号变更与会话签发串行化

状态：接受

## 问题

会话缓存的在途回填可能发生在撤销之后，令已删除会话重新可用。登录校验与签发分离时，管理员禁用或重置可能发生在两者之间。自助改密无条件写入也可能覆盖并发重置。编辑及导入入口未完整撤销状态变化后的会话。

## 决策

MySQL 是会话唯一权威，移除会话 Redis 副本、回填及提交后删除流程。访问令牌通过现有摘要唯一索引查找。签发、刷新和按用户撤销按“账号行、会话行”的顺序加锁；签发必须核对认证时摘要与当前账号的启用、强制改密状态。多账号撤销按编号排序。

自助改密使用旧摘要及启用条件原子替换，受影响行数必须为一；哈希编码升级冲突拒绝本次认证。账号编辑中的禁用及导入更新与会话撤销同事务。登录成功日志与签发同成败，失败审计以独立事务保留。

短信重置在锁定当前账号后再次核对手机号；验证期间解绑、更换手机号或删除账号时，保留统一响应且不写入密码。管理员编辑和个人资料更新先读取被锁定的当前账号，再比较变更；岗位关系使用相同锁顺序下的当前读，避免旧事务快照漏撤销会话或留下历史岗位。

## 代价与验证

每次访问令牌校验增加一次唯一索引查询，减少分布式状态和失败补偿分支。未来只有在真实负载证明需要、且能证明即时撤销语义的情况下再引入授权缓存。

单元回归覆盖编辑禁用、导入本人联系方式、并发凭据条件更新及哈希升级冲突。`SessionConcurrencyIT` 在真实 MySQL 中验证签发与改密竞争、刷新与禁用竞争、刷新单次轮换以及成功/失败审计的回滚边界。`SessionPersistenceIT` 验证真实账号和角色服务的令牌失效。

`UserProfilePersistenceIT` 验证空值解绑、岗位两侧同步、回滚和旧事务快照下的连续编辑。
